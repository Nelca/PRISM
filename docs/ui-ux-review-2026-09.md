# PRISM UI/UXレビュー（2026-09）

## 結論

PRISMの機能は、拠点登録から評価、価値算定、財務試算、対策・判定、開示、監査証跡まで一貫していました。一方、機能追加のたびに同じ画面へ一覧・詳細・編集・分析が積み重なり、「今やること」「次に進む場所」「全体の進捗」が見つけにくい状態でした。

今回の改修では、業務フロー自体は維持したまま、ホームを行動起点に再構成し、一覧・詳細・分析・登録をそれぞれ固有URLへ分離しました。あわせて、進捗指標の意味、スマートフォンでのナビゲーション、キーボード操作、表・グラフ・ダイアログのアクセシビリティを修正しています。

レビュー後にCodexが実装全体を再点検し、重大度P0の未対応はなし、P1の指摘はすべて対応済みと判断しました。

## レビュー方法

- 情報設計・ルート構成、アクセシビリティ、進捗指標・業務上の意味を別々の担当で並列レビュー
- 主要画面のコード、導線、空状態、エラー状態、操作状態を確認
- デスクトップと375px幅のモバイル表示をブラウザで確認
- 指摘反映後にCodexが導線、画面責務、用語、数値の意味、キーボード操作を再レビュー
- 型チェック、Lint、単体・結合テスト、DBテスト、本番ビルドで回帰を確認

## 主な問題と対応

| 領域 | レビュー時の問題 | 対応 |
| --- | --- | --- |
| 全体ナビゲーション | デスクトップ前提で、現在地と次の作業が弱い | レスポンシブなアプリシェル、現在地表示、モバイルドロワー、スキップリンクを追加 |
| ホーム | 数値の閲覧が中心で、次に何をすべきか判断しにくい | 「次にやること」を最上部へ置き、担当ステップと対象へ直接遷移する行動起点の画面へ変更 |
| 進捗 | 評価対象、算定済み、代表値選択済みの分母が混在 | 絞り込み・詳細評価・算定・代表値選択を独立した意味で集計。厚生価値のみの対象は代表値選択不要として扱う |
| 画面責務 | 一覧、詳細、登録、分析が1画面に混在 | 拠点登録、各種インポート、課題詳細、価値算定、比較分析、根拠、拠点別財務、拠点別判定、開示指摘、監査台帳を固有URLへ分離 |
| 価値算定 | 詳細分析が代表値選択より先に見え、主操作が埋もれる | 代表値選択を先頭へ移動。詳細分析は折りたたみと専用分析画面へ段階的に開示 |
| 対策と判定 | 判定操作と候補分析が長い同一画面に重複 | 拠点画面は判定・選択・反映先に集中し、比較は読み取り専用の分析画面へ分離 |
| 開示 | 指摘一覧と1件の対応、PDF取込、下書きが混在 | 取込、下書き、指摘詳細を分離。指摘から関連する評価対象へ直接つなぐ |
| 記録 | 日常確認と技術的な監査情報が同じ長い画面に混在 | 変更履歴、入力・係数、パラメータ版、判定件数へ分割。ハッシュ等は技術情報として折りたたむ |
| タスク導線 | タスクから画面先頭へしか移動できない | 課題・拠点・指摘の対象IDを含む直接URLへ変更 |
| モーダル／ドロワー | 閉じたモバイルナビがフォーカス対象に残る可能性、送信中のフォーカス管理不足 | 非表示時はアクセシビリティツリーから除外。フォーカストラップ、Escape、復帰先、送信中状態を修正 |
| 表・グラフ | 横長表の操作領域とグラフの代替説明が不足 | 横スクロール領域に名前とキーボードフォーカスを付与。グラフへ`role=img`、タイトル、説明を追加 |
| エラー／空状態 | エラーの通知方法と復帰先が画面ごとに不統一 | `role=alert`、送信ボタンの状態制御、日本語404と復帰リンクを追加 |
| 数値の説明 | 手法間比較の方向を誤読しうる文言が存在 | 比較方向を統一し、既存保存データにも表示時の補正を適用 |

## 現在の画面構成

1. ホーム: 全体進捗、次にやること、重要な論点
2. 拠点とデータ: 拠点一覧、拠点登録、PRTR・廃棄物・土地利用の取込
3. 評価対象の絞り込み: 全体一覧、課題別詳細
4. 価値の算定: 対象一覧、課題別の代表値選択、比較分析、根拠
5. 財務への影響: 拠点一覧、拠点別詳細
6. 対策と判定: 拠点一覧、拠点別の操作、読み取り専用分析
7. 開示への反映: 指摘一覧、PDF取込、指摘別対応、下書き
8. 記録: 概要、変更履歴、入力・係数、パラメータ版、判定件数

## Codexによる再レビュー

### 確認結果

- 主要な業務タスクには、ホームまたは各一覧から対象を特定した直接リンクで到達できる
- 一覧画面は全体把握、詳細画面は1対象の操作、分析画面は読み取りに責務を限定できている
- 詳細画面には一覧へ戻る導線があり、存在しないIDは日本語の404へ遷移する
- 主要操作は画面上部にあり、ガイドより先にユーザーが行動を判断できる
- モバイルではサイドバーがドロワーになり、閉じた状態でフォーカスされない
- キーボード利用時にフォーカスが視認でき、ダイアログ内を循環し、閉じた後に起点へ戻る
- 表は狭い画面で横スクロールでき、スクロール領域とグラフには読み上げ可能な名前がある
- エラー、処理中、空状態、対象なしの状態が明示されている
- 進捗、残タスク、財務の注意点が同じ算出ロジックを参照し、画面間で意味がずれない

### 残存する低優先度の改善候補

- 実ユーザーによるタスク完了時間、迷い戻り、誤操作の計測は未実施。5〜8名程度の業務担当者テストで確認すると精度が上がる
- 拠点・指摘が100件を超える運用では、一覧の検索、絞り込み、ページングを追加する余地がある
- グラフには代替説明を追加したが、色覚特性別の実機確認とスクリーンリーダーによる通しテストは継続課題

これらは今回の主要導線を阻害する問題ではなく、実運用データと利用状況を得た後に優先度を判断する項目です。

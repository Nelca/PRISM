## 0. エグゼクティブサマリー

### 何を作るのか

企業が保有する環境データを、**個別の投資判断・稟議の閾値をまたぐかどうかの判定**に使える形式に変換するレイヤー。計測は行わず、既存の計測データと公開データベースを入力として受け取る。

出力は3層に分かれる。

1. **ValuationRecord** — 同一の物理量(取水量、土地改変面積等)に対し、複数の貨幣化手法を並列適用した結果。手法間の差を「精度のばらつき」と「問いの違い(価値概念・エンドポイント被覆・割引率・地理較正)」に分解して示す
2. **DecisionRecord** — ValuationRecordのレンジを、実際に社内にある決定(投資稟議、調達契約更新、拠点計画等)の承認閾値と突き合わせ、レンジが閾値をまたぐか否かを判定する
3. **DisclosureView** — 同じレコードから、SSBJ等の基準別に組み替えた開示文を生成する

### なぜ今なのか

日本のSSBJ開示義務化が2027年3月期からプライム大企業に始まり、段階的にプライム全体(約1,600社)へ拡大する。規制が需要を強制的に作るため、市場教育コストを規制当局に肩代わりさせられる。ただしIDC Japanの予測では、SSBJ・CSRD対応投資は2026年まで2桁成長した後、**2027年に先行投資の反動で一時的に鈍化**する。本プロダクトのMVPローンチ時期はこの鈍化局面に重なるため、ロードマップ上の重要なリスクとして扱う(10章参照)。

### なぜ他社にできないのか(v2)

自然の貨幣価値換算は、手法によって同一項目で2桁(鉱物資源では5桁)の差が出る。しかしこの事実だけでは差別化にならない。**GIST Impact、Natcap、NatureAlpha、IFVI(Capitals Coalition統合後)を含む既存プレイヤーは全員、1つのhouse methodか、公共財としての単一係数のいずれかを提示している。**手法を複数並べて比較すること自体は技術的障壁が低く、既存プレイヤーが数四半期で追随しうる。

真に手が付けられていないのは次の2点である。

- **乖離の原因分解**:手法AとBが7倍違うとき、その差のうち何倍が「問いの違い(厚生価値か交換価値か)」で、何倍が「エンドポイント被覆の違い」で、何倍が「割引率・地理較正の違い」かを機械的に説明する層。house methodを持つ会社は自社手法を正とするため、他社手法との差を分解する動機が構造的に弱い
- **決定の閾値判定**:出したレンジが、実際に社内で回っている稟議・投資判断の承認基準をまたぐかどうかを判定し、またがない場合は「効かない」と安く速く確定させる層。EP&L(15年運用)、内部炭素価格(2/3がシャドウプライスに留まり意思決定に届いていない)のいずれも、この判定を提供していない

### 中核的な設計思想(v2)

M&Aのデューデリジェンス実務からは、**成果物の文法**(調整ブリッジ、フットボールチャート、感応度分析)だけでなく、**その文法が存在する理由**を輸入する。DDにおいてレンジ表示(フットボールチャート)が使われるのは、精度の限界を誠実に示すためではなく、**提示価格がレンジのどこに位置するかを見て、交渉の焦点を絞るため**である。レンジは結論ではなく、結論を出すための道具である。εにおいても同様に、レンジそのものが製品の価値ではなく、**レンジが決定の閾値をまたぐかどうかの判定**が価値の本体となる。

## 1. 目的関数(Stage 0) ※v1から変更なし

### 1.1 終端目標

> **生態系サービスの価値が交換可能になり、その保全・回復に経済的インセンティブが働く構造が成立している状態。**

炭素に限定しない。生物多様性、水、土壌を含む生態系サービス全般を対象とする。

### 1.2 最大化する量

```
アウトカム総量 = 反事実的確実性 × 到達規模
```

「介入がなければ起きなかった物理的環境アウトカム」で成立度を測定する。規模はこの式の一項であり、独立した要件ではない。

### 1.3 制約条件

| # | 制約 | 位置づけ |
|---|---|---|
| C1 | 自分が構築するプロダクトを経由すること | 固定制約 |
| C2 | 個人で構築可能であること | 固定制約 |
| C3 | 長期構造変化を優先(短期の規制ウィンドウは手段) | 優先順位 |
| C4 | 事業性は持続手段(目的ではない) | 非営利・標準化団体モデルも候補空間に含む |

**v2注記:** C2(個人構築可能)は、9.3で述べる通り買い手層が財務・経営企画・事業部決裁ラインへ広がるにつれて、営業難度が上がる方向に効く。この緊張関係は未解決のまま11章に残す。

### 1.4 評価軸

- **追加性**:介入がなければ起きなかった変化を生むか。情報提供のみでは弱い
- **レバレッジポイント**(Meadows):自律実行 > 意思決定点への統合 > 標準化 > 集約・アクセス
- **5問フレームワーク**:反事実、乗数、防御力、持続性、不可逆性
- **評価時点**:10年後の期待アウトカムで統一(恣意的な採点操作を防ぐため)

## 2. 理想状態と介入点(Stage 1) ※v1から変更なし

### 2.1 2035年の理想状態(構造命題)

| # | 命題 |
|---|---|
| P1 | 計測が意思決定コストを下回っている |
| P2 | 自然に関する主張が第三者的に成立し、反証可能である |
| P3 | 受益者から供給者への対価の流れが恒常化している |
| P4 | 土地転用・調達・融資の決定場面に、生態系価値の経済的帰結が提示されている |
| P5 | 上記が特定主体の存続に依存せず、規制・会計基準・契約慣行に埋め込まれている |

### 2.2 価値交換の因果連鎖と欠落箇所

```
計測 → 単位化 → 検証 → 価格形成・交換 → 意思決定注入 → 実行
```

| 領域 | 欠落箇所 |
|---|---|
| **炭素** | 単位(tCO2e)は普遍、価格機構(ETS)も存在。欠けているのは検証の信頼性と意思決定注入 |
| **炭素以外** | 最上流から欠落。計測は高コスト、単位は不在(生物多様性は空間固有で代替不可能)、したがって検証・価格・交換が建たない |

**v2での再確認:** 内部炭素価格の実証データ(4.2節)は、「意思決定注入」が炭素という最も条件の良い領域ですら未解決であることを示す。P4(決定場面への提示)は、炭素ですら達成されていない。

### 2.3 構造的緊張とその解消

**空間固有性 vs グローバル規模。** 生物多様性は炭素と違い代替可能な単一コモディティにならない。これはC3(規模)と衝突するように見えるが、**資産はローカル、測定方法論と信頼構造はグローバル**という分離で解消する(不動産と同型)。規模を「単一市場の大きさ」でなく「方法論が適用される決定の総量」で取る。

**(D) 方法論・係数の公共財化(最重要)**

IFVIは2022年にHBSインパクト加重会計プロジェクトからスピンアウトし、VBAと共同で開発を進めてきたが、**2025年11月にCapitals Coalitionへの統合が完了**し、新設のImpact Valuation Standards Board(IVSB)が統括している。IFVIのVTPC(技術実務委員会)とCapitals CoalitionのValue Commissionが統合された。Capitals Coalition自身が「10年の成長の後、いまは協働・標準化・統合の時期」と位置づけている。

IFVIは大気汚染・土地利用転換・廃棄物・水質汚染をカバーする暫定手法と、**約10万件の価値係数を集めたGlobal Value Factor Database**を公開しており、投資家・企業がそのまま適用できる。実装は「企業データ × 価値係数」に集約されており、例えばCO2 1トンに236USD(社会的費用)を掛けるだけで、企業側が独自に調査してoutcomeを定義する必要はない。ただし完全に完成しているのはGHGのみで、General Methodology 2、適正賃金、水消費、労働安全、製品インパクト枠組みは公開草案段階(水消費は2026年3月に最終版)。

**含意:** 係数もデータも、εの競争領域ではない。GIST/Natcap/IFVIが既に埋めている。

### 4.2 需要側の実証データ(新設・最重要)

εが解こうとする「非財務の財務判断への組み込み」は、実は**炭素という最も条件の良い領域で既に試され、失敗している。**この事実は供給側の調査だけでは見えず、需要側を確認して初めて判明した。

**内部炭素価格(ICP)の運用実態**

WBCSD 2025年分析によれば、内部炭素価格を利用する企業は14〜18%にとどまり、そのうち約2/3は**シャドウプライス**(意識喚起のための想定コストで、実際の課金を伴わない)である。実務者の評価は明確で、「シャドウ炭素価格は投資判断の指針にのみ使われP&Lには課金されないため、しばしば『本物の金ではない』と見なされる」。CDPの採点実務では、「数字をスライドに載せるだけで実際の決定に組み込まない企業がある。採点者は、その価格が現実の結果を変えた証拠(設備投資の優先順位変更、サプライヤーからの撤退)を探す。証拠がなければ、その開示は演出と読まれる」とされている。

炭素は実市場価格があり、bpは1998年の社内排出量取引制度以来、内部炭素価格を使い続けている。それでも大多数の企業では意思決定に届いていない。

**EP&Lの15年間の運用実績**

PUMAは2011年、世界初のEP&Lを公表した(2010年度の環境影響を1億4,500万ユーロと算定)。手法はPwCとTrucostが2011年に開発し、後にKeringがPwCの支援で改良したもの。PUMA自身が2023年アニュアルレポートで次のように記述している。「EP&Lは精密な測定ツールではないが、バリューチェーンのどの段階で影響が最大かを示し、どこに注力すべきかの良い指標を与える」。15年経っても、用途は**ホットスポット特定と優先順位付け**にとどまり、財務判断そのものには組み込まれていない。

**日本での状況**

日本での導入事例はエーザイ、SOMPOホールディングス、積水化学、KDDIなど数例(多くが部分的導入)にとどまる。積水化学は特に象徴的で、**貨幣評価額そのものは開示資料に掲載せず**、当期利益に対するステークホルダー包括利益の比率のみを、経年変化として開示している。企業自身が、単一の貨幣評価額を外に出すことのリスクを認識していることを示す実例である。

**ESG DDにおける定量化ギャップ**

BCG・Gibson Dunn調査では、回答者の半数超が「ESGの発見事項がバリュエーションに与える影響を定量化する指標を持っていない」と回答。回答者の14%は「ESG要因が企業価値に与える影響を十分に理解できない」ことを課題として挙げた。KPMGの2024年調査も同様の結論で、「スコープが明確で信頼できるターゲットデータがあっても、ディールメーカーは発見事項の定量化とディールへの財務影響評価に苦労する。これは主に、目的に適合したベンチマークデータの入手可能性の問題を反映している」。

**この4つの事実から得られる結論:** 単一値方式(EP&L、シャドウプライス)は、精度が低いから使われないのではない。**数字が何にも拘束されず、決定を変えた証拠を残せないから使われない。**これはεの当初の想定(手法間の乖離を隠す単一値が信頼を損なう)とは異なる原因であり、対処法も異なる。求められているのは「より正確な1本」でも「複数手法の中立併記」でもなく、**「この数字は、この決定を変えるか」という判定**である。

### 4.3 学術的批判の到達点

King & Pucker(2021, SSIR)は、企業の惑星規模の影響を貨幣化する新提案は「魅惑的だが、実行不可能かつ危険」と論じた。IFVI側(Zochowski, Panella, Carpenter)はこれに反論し、影響の貨幣化は「文脈と科学に基づく許容範囲への収束(bounded flexibility)」を目指すものであり、単一の硬直した解釈を押し付けるものではないと述べた。

この論争は2025年のNature Sustainability誌の論説(King本人を含む15名連名)にまで続いている。同論説は、影響評価の便益は「透明・方法論的に堅固・参加型・倫理的に根拠づけられ、重要性と費用対効果を考慮した」科学的アプローチを採ってはじめて実現しうる、という**条件付きの支持**にとどめている。2026年にはJournal of Management Inquiryで批判的検討も出版されている。

**含意:** εが単一値ではなくレンジと前提の構造化を志向する設計判断は、この学術的到達点(bounded flexibility)と整合する。ただしそれだけでは製品にならず、4.2節の実務的教訓(拘束力の欠如)と組み合わせる必要がある。

## 5. バリュープロポジション(v2で中核を改訂)

### 5.1 表と裏

| | 内容 |
|---|---|
| **表(顧客が買う理由)** | 3つの数字:未内部化コスト・内部化率 / 期待損失 / 対策ROI。**加えて、当該数字が具体的な決定の閾値をまたぐか否かの判定** |
| **裏(競合が勝てない理由)** | 手法間の乖離を「精度のばらつき」と「問いの違い」に分解する辞書。house methodを持つ会社は自社手法を正とするため、この分解を行う動機が構造的に弱い |

3つの数字自体は模倣可能。乖離分解の辞書と、決定への接続は模倣困難である。

### 5.2 対象ユーザーとニーズの構造(新設)

3つの部門が別々の困りごとを抱えているように見えて、実際には同一の出力で同時に満たされる。

| 主体 | 実際に困っていること | 必要な性質 |
|---|---|---|
| **A. サステナビリティ/IR担当者** | SSBJで財務影響を書かねばならないが根拠が薄い。コンサルに頼むと数字が1本返るだけで、なぜその数字かを社内で説明できない。担当が変わると再現もできない | 説明可能性 |
| **B. CFO/財務・経営企画** | サステナ部門から来た数字は単一値で誤差がないため、感度分析にかけられない。だから使わない | 使用可能性(感度分析可能性) |
| C. 事業部・決裁ライン | 稟議書に環境欄があっても埋められない、埋めても読まれない | 判断可能性(効くか効かないかの確定) |
| D. 投資家・銀行・監査法人 | 中期。信頼表明グレードで対応 | 保証可能性 |

**説明可能性と使用可能性は、「前提が構造化されているか」という同一の性質の表裏である。**手法AとBの差が「問いの違い」だと分かれば、Aチームは社内で説明でき、Bチームはその差の幅を感度分析に使える。この2つを別々の機能として作る必要はない。

### 5.3 なぜ模倣されないか(v2改訂)

| 防御 | 内容 |
|---|---|
| **乖離分解の辞書** | 各手法がどのエンドポイントを含み/除外し、どの割引率・価値概念・地理較正を用いているかのメタデータ。手法が増えるたびに更新が必要で、house methodを持つ競合には構築する動機が構造的にない |
| **決定閾値との接続実績** | 「この論点は過去にどの決定を変えたか/変えなかったか」の記録。評価を都度売るビジネスモデルには蓄積されない |
| **前提と実績の照合履歴** | 数年分蓄積して初めて意味を持つが、時間でしか買えない資産 |
| **上流ポジション** | ERP内で完結する機能ではないため、ERPに吸収されない |

**v1からの変更:** 「中立性」はこの表から削除した。中立性は本来ISSB/IVSBのような標準設定主体が占めるべき立場であり、一民間企業の防御力の根拠にはならない。

### 5.4 死因への対処

| 死因 | 対処 |
|---|---|
| **A. 市場教育コスト** | 規制が既にある一点(SSBJ気候→自然)に絞り、市場教育を規制当局に肩代わりさせる |
| **B. ERP・大手プラットフォームによる吸収** | 上流ポジションを取る(中立性ではなく、乖離分解辞書の独自性で防御) |
| **C. 効率化ツールへの転落** | 開示生成を入口(低価格)に降格し、**決定閾値判定を製品の顔にする** |
| **D. 規制実行の遅延** | 気候起点で立ち上げ、自然を後から載せる。収益がS3のタイミングに依存しない |
| **E. 単一値方式と同じ運命(新設)** | EP&L・内部炭素価格が辿った「意識喚起止まり」を避けるため、出力を稟議の**判定式そのもの**に接続する設計を必須とする(9.3節M6) |

## 6. ビジネスモデル ※DD輸入の論理は維持、量的な使われ方を明確化

### 6.1 DDからの輸入(再定義)

輸入するのは成果物の文法だけでなく、**その文法が存在する理由**である。DDでフットボールチャートが使われるのは、精度の限界を誠実に示すためではなく、提示価格がレンジのどこに位置するかを見て交渉の焦点を絞るためである。εにおいても、レンジ自体ではなく、**レンジが決定の閾値をまたぐかどうかの判定**が価値の本体である。

| DDの道具 | εでの対応 |
|---|---|
| Quality of Earnings(調整ブリッジ) | 報告財務 → 自然調整後財務 |
| フットボールチャート | 手法別レンジの併記。**ただし目的は「閾値をまたぐか」の判定** |
| 感応度分析・トルネード図 | どの前提がレンジを支配するか。レンジを支配する前提が分かって初めて「どこを深掘りすべきか」が決まる |
| Red flag report | 重大度順の論点一覧 |

### 6.2 発行体課金の呪いを破る:VDDモデル ※v1から変更なし

売り手が費用を負担するベンダーDD(VDD)が買い手に信頼される理由は3つ:提供者が買い手に信頼表明書を発行し専門家責任を負う、手法が職業的規範で標準化されている、提供者にとって一件の顧客より全案件での評判の方が価値が大きい。信頼表明書は、開示企業が費用を払いながら、成果物の名宛人を投資家・銀行にする仕組みである。

### 6.3 年度サイクルでの使われ方(新設)

```
Q1 開示準備   既存データ投入 → 複数手法で並列貨幣化 → 手法間の乖離が見える
              → 乖離の原因分解(問いの違いか精度の差か) → 代表値を選び理由を記録
              → SSBJ財務影響欄の草案(DisclosureView)

Q2 決算・開示  開示。前提台帳が保証実施者の質問に答える材料になる

Q3 予算・投資  同じレコード(ValuationRecord)を稟議フォーマットに接続
              → 稟議の承認閾値と照合(DecisionRecord)
              → 閾値をまたがない案件は「効かない」と確定して終了(安い・速い)
              → またぐ案件だけ深掘り(追加課金)

Q4 中計・方針  対策のROI 2軸比較、シャドウプライス水準の設定根拠
              社内制度への拘束方式(稟議判定式/予算賦課/契約条項)の見直し
```

単発コンサルにできないのは、**開示のために作った数字が、そのまま投資判断に流れる**ことである。現状は両者が別々に作られ、整合していない。SSBJがシングルマテリアリティ(自社財務への影響)である以上、開示用の数字(交換価値)と投資判断用の数字は本来同一であるべきだが、実務では別のベンダー・別の担当が別々に作っている。

### 6.4 提供形態と課金 ※v1から変更なし

| ティア | 内容 | フェーズ |
|---|---|---|
| スクリーニング | セルフサーブ、概算把握 | MVP |
| 開示グレード | レビュー付き、監査対応可能な前提台帳込み | MVP |
| 信頼表明グレード | 専門家責任を伴い、投資家・銀行を名宛人にできる | フェーズ3 |

## 7. カテゴリ体系 ※v1から変更なし

### 7.1 分類軸はTNFD構造を採用する

ESRS E1〜E5を主軸にするのは誤り。理由:マテリアリティ概念が違う(ESRSはダブル、SSBJ/ISSBはシングル=財務)、ISSB S3の骨格はTNFDでありTNFDはIPBESの5ドライバーで構成、ESRSは「依存」と「影響」を分離していない。

財務マテリアリティの本体は「依存」側にある。内部表現はTNFD 3軸(依存/影響ドライバー/自然の状態)に置き、ESRS等は出力ビューとして辞書で組み替える。

### 7.2 貨幣化のティア分け

| 軸 | カテゴリ | 扱い | 根拠・制約 |
|---|---|---|---|
| 影響 | 気候変動(GHG) | ティアI | GX-ETS価格・炭素の社会的費用。実市場価格が存在する唯一のカテゴリ |
| 影響 | 汚染 | ティアI | CE Delft 3,000物質 + LIME3 |
| 影響 | 土地・淡水・海洋利用改変 | ティアII | ESVD便益移転。不確実性最大 |
| 影響 | 資源利用/再生 | 水=I / 生物資源=II / 鉱物=III | 鉱物は手法間5桁の乖離 |
| 依存 | 水供給 | ティアI | 代替費用、水価格、生産関数 |
| 依存 | 送粉 | ティアII | 生産関数(収量減) |
| 状態 | 生態系範囲・状態・種 | III(物理単位のみ) | TNFD自身が単一指標の不在を認めている |

### 7.3 気候の扱い ※v1から変更なし

GHGインベントリの算定エンジンは作らない。財務影響変換は自前で作る。気候を含める判断は、唯一実際に観測可能な市場価格が存在し利用者が検算できる錨になること、他カテゴリの将来像を示す実例になることから、製品全体を成立させる。

## 8. 中核エンジンの設計(v2:DecisionRecordを追加)

### 8.1 設計の一行要約(改訂)

> 出力は3層でできている。**(1)金額 + それが何を意味するか + どこまで信頼できるか(ValuationRecord)、(2)その金額が具体的な決定の閾値をまたぐか(DecisionRecord)、(3)基準別に組み替えた開示(DisclosureView)。**

v1では(1)を最終出力としていたが、既存プレイヤー(GIST Impact、Natcap、IFVI)も同種の出力を持っている。差別化になるのは(2)であり、(1)はその入力に位置づけを変える。

### 8.2 価値概念の分離(最重要規律) ※v1から変更なし

| 価値概念 | 意味 | 用途 |
|---|---|---|
| **交換価値** | 市場でやり取りされる価格に相当 | 会計接続、**財務マテリアリティ(SSBJ)**、依存側 |
| **厚生価値** | 社会が被る損失(WTP基準) | 社会的コスト表示、**インパクトマテリアリティ(ESRS)**、影響側 |

この2つは足せない。全金額に価値概念タグを付与し、異なる概念の合算をシステムが物理的に禁止する。

**v2での運用範囲の絞り込み:** DecisionRecordが接続する投資判断・稟議は、原則として交換価値のみを扱う。厚生価値は開示(DisclosureView)側でのみ用い、当面は決定閾値判定の対象から外す。範囲を絞ることで実装負荷を下げる。

### 8.3 適合度スコア(5次元) ※v1から変更なし

便益移転の誤差は研究地点と対象地点の乖離から生じる。

| 次元 | 測定内容 |
|---|---|
| 生態的適合 | 生物群系の一致度 |
| 社会経済的適合 | 一人当たり所得・人口密度の差 |
| サービス定義適合 | 分類コード(CICES/TEEB)の階層一致度 |
| 時間的距離 | 研究年と評価年の隔たり |
| 空間スケール適合 | 研究地面積と対象面積の比、代替地の有無 |

```
適合度 = 加重幾何平均(5次元)
ティア判定: A = 一次評価相当の信頼 / B = 補正付き移転で実務使用可 / C = 桁の把握のみ
```

### 8.4 補正 ※v1から変更なし

```
調整値 = 原値
       × 購買力平価換算(研究国 → 日本)
       × (対象地所得 / 研究地所得)^η
       × 一般物価デフレータ
       × 生態系サービス相対価格上昇係数^(経過年数)
       × 面積スケーリング
```

### 8.5 不確実性の3層 ※v1から変更なし

| 層 | 内容 | 扱い |
|---|---|---|
| i. パラメータ不確実性 | 同一条件の推計値の分布 | 分位点として算出、モンテカルロに投入 |
| ii. 移転誤差 | 適合度から推定される移転行為由来の誤差 | ティアに対応する誤差分布として投入 |
| iii. スコープ・方法論不確実性 | 何を含め何を除外したか | 数値に混ぜず、除外事項リストとして別枠で出力 |

### 8.6 乖離分解(v2で新設・製品の中核)

同一物理量に複数手法を適用した際、その差を4つの原因に分解する。

```
乖離分解 {
  対象物理量とValuationRecord群(手法ID付き、N≧2)
  差の分解:
    価値概念の違いによる寄与    ← 交換価値 vs 厚生価値。最大の寄与になることが多い
    エンドポイント被覆の違いによる寄与  ← 各手法が何を含み/除外しているか
    割引率の違いによる寄与
    地理較正・購買力平価の違いによる寄与
  分解後の「同じ問いに答えている手法群」を再グループ化
  → 同一グループ内での代表値選択(前年度手法・基準言及手法を事実として提示)
}
```

**この分解ができるかどうかが、製品全体の成否を分ける唯一の技術的前提である**(11章参照)。IFVI、CE Delft環境価格ハンドブック、LIME3が、各手法のエンドポイント被覆・割引率・価値概念をメタデータとして公開しているかを、フェーズ0で最優先に検証する。

### 8.7 ValuationRecord(貨幣化の原子単位) ※v1からタグを追加

```
ValuationRecord {
  影響カテゴリ / 物理量 / 対象地点
  価値概念タグ           ← 交換価値 or 厚生価値
  手法ID(版番号付き)
  中心値 / 分位点レンジ
  適合度ティア(A/B/C) と 5次元スコア内訳
  適用した補正の一覧
  出典
  除外事項リスト
  エンドポイント被覆メタデータ  ← 8.6の乖離分解に使用。この項目の充実度が製品の生死を決める
  再計算ハッシュ
}
```

### 8.8 DecisionRecord(意思決定の原子単位・新設)

```
DecisionRecord {
  決定対象           … 投資稟議 / 調達契約更新 / 立地 / 事業計画
  決裁者・決裁日・承認閾値   ← 既存の社内決裁プロセスに寄生する(新設プロセスは作らない)
  関連するValuationRecord群(交換価値のみ)
  自然調整後NPV(通常NPV + 自然関連コスト/便益)
  レンジ(下限/中心/上限)
  ★判定 … 結論を変えない(閾値をまたがない) / 閾値をまたぐ
  ★判定がまたぐ場合のみ:深掘り推奨と、レンジを支配する前提
  決裁時の実際の選択と理由
  拘束方式  ← 参考記載/稟議判定式への組込み/予算賦課/契約条項。9.3(M6)参照
  前提の実績照合(n年後、当初前提と実績の乖離)
}
```

★判定が製品の価値の中心である。またがない場合は「効かない」と確定させて終了する(安い・速い・防御可能)。またぐ場合のみ深掘りし、そこが課金対象になる。

### 8.9 エンドポイント重複検出 ※v1から変更なし

貨幣化係数は互いに損害エンドポイントを重複してカバーする。システムは自動控除せず、検出し、選択肢を示し、選択を記録する。相殺は既定で禁止し、有効化する場合は根拠・地理的時間的一致・恒久性の説明を必須とし、総量と純量を必ず併記する。

### 9.2 モジュールと優先順位の再整理

v1では8モジュールを均等に「薄く全部入り」としていたが、v2では**購入理由となるモジュール(M3〜M6)**と**継続理由となるモジュール(M8)**を明確に分離する。

| # | モジュール | v2での位置づけ |
|---|---|---|
| M1 | 対象定義とLocate | 従来通り。既存プレイヤー(Natcap等)の機能と重複するため薄く実装し、自前構築を避ける余地を検討 |
| M2 | 評価実行(深度可変) | 従来通り |
| **M3** | **貨幣化エンジン(複数手法の並列適用)** | **購入理由の一部。**係数自体は既存資産(IFVI等)を使い、自前構築するのは複数手法の切替・横断比較の基盤 |
| **M4** | **乖離分解(旧:集約と代表値確定)** | **購入理由の中心。**乖離を「精度のばらつき」と「問いの違い」に分解する。ここが8.6節の中核機能であり、実装可否がフェーズ0の最優先検証事項 |
| **M5** | **財務接続** | **購入理由の一部。**金額を単独で出すのではなく、比較先(営業利益比、減損テストの前提、格付・資本コストへの影響)とセットで出す |
| **M6** | **対策評価と意思決定注入** | **購入理由の中心。**2軸比較に加え、選んだ対策を社内制度のどこに接続するか(拘束方式)の設計と記録を機能として持つ。ここがないと内部炭素価格と同じ「本物の金ではない」という扱いを受ける |
| M7 | 開示生成と整合検証 | **必要(競合にあるからではなく、予算科目と締切が存在する唯一の入口だから)。**自社レコードから自社の開示を生成する点で、他社文書のギャップ検出(NEC型)とは別物であり陳腐化しない |
| M8 | 記録・版管理基盤 | **継続理由。購入理由ではない。**初日から構造として完全である必要があるが、営業上の訴求点としては前面に出さない |

### 9.3 主要モジュールの要点(M4・M6を重点的に改訂)

#### M4:乖離分解(旧:集約と代表値確定。v2で最重要モジュールに格上げ)

```
乖離分解(手法群):
  各手法のValuationRecordからエンドポイント被覆・割引率・価値概念・地理較正を抽出
  → 差を4要因に分解(8.6節)
  → 「同じ問いに答えている」手法同士を再グループ化
  → グループ内で代表値を選択(前年度手法・基準言及手法は事実として提示、推奨はしない)

手法変更時: 変更理由の入力を必須化し、前年度手法での再計算値を並記
           (手法変更の差分と実態変化の差分を分離)
```

**手法間の乖離倍率の表示だけでなく、乖離の「原因」の表示が必須要件である。**これがない場合、v1と同様「3本並べただけ」に退化し、単一コンサル納品物に対する優位性が消える。

#### M5:財務接続(改訂)

```
自然調整後利益(交換価値のみ)
  報告営業利益(監査済み) − 依存リスクの正常化調整 − 将来内部化見込みコスト
  = 自然調整後営業利益

期待損失の提示は単独で行わず、必ず比較先とセットにする:
  当該事業の営業利益比 / 減損テストの前提を変えるか / 格付・資本コストへの影響
```

厚生価値ビュー(社会的費用・内部化率)は開示専用とし、投資判断への接続からは分離する(8.2節)。

#### M6:対策評価と意思決定注入(v2で拘束方式の設計を追加)

```
対応手段の4類型:回避/低減/移転/受容

自然調整後NPV = 通常NPV + Σ 回避される自然関連コスト(割引後)
比較表示(2軸):横軸=単位投資あたり財務効果 / 縦軸=単位投資あたり環境アウトカム(物理量)

★判定(DecisionRecord):レンジが承認閾値をまたぐか
  またがない → 「効かない」と確定、5分で終了、追加課金なし
  またぐ     → 深掘り推奨(課金対象)、レンジを支配する前提を提示

拘束方式の選択と記録(新設):
  弱  … 稟議書に参考値として記載(内部炭素価格の2/3と同じ運命をたどるリスク)
  強  … 稟議の判定式そのものを自然調整後NPVに変える
  強  … 対象拠点の自然関連コストに実際に予算賦課する(本物の金)
  強  … 調達契約の更新条件に組み込む
  → 選んだ方式に応じて出力先のフォーマットを変える(判定結果を渡すか、金額を渡すか)
```

#### M7:開示生成と整合検証(判断軸を修正)

**位置づけ:公表前の自己点検であり、他社評価ツールではない。**

必要性の根拠を「競合にあるから」から「プロダクトとして必要か」に置き直すと、次の3点で必要と判断できる。

1. 予算科目と締切が存在するのはここだけであり、今年度導入する動機の起点になる
2. 物理データが社内で揃うのが開示準備の瞬間であり、データ取込の自然なタイミングと重なる
3. SSBJが財務影響の開示を求める以上、社内の投資判断(M6)と開示(M7)が同じ前提・同じレコードから出ることに整合性の価値がある。両者が別ベンダー・別担当で作られている現状こそが、単発コンサルには埋められない隙間である

```
段階1: AIでDisclosureClaimを抽出(抽出のみ、真偽判定はしない)
段階2: 主張タイプの分類(状態/定量/傾向/比較/純量/将来約束)
段階3: 根拠の紐付けと充足度判定
段階4: ギャップ類型の判定(G1根拠不在〜G8約束の裏付け欠如)
```

推奨アクションは3種:①主張を弱める ②根拠を追加取得する(深掘りへの導線=課金) ③意図的判断として記録する。

#### M8:記録・版管理基盤(位置づけを「継続理由」に限定)

初日から構造として完全である必要があるが、購入の決裁根拠として前面に出す機能ではない。

```
AssumptionEntryの蓄積、再計算ハッシュ、係数セットの版管理、ライセンス区分の制御
+ (新設)DecisionRecordの前提と、n年後の実績との照合。前提が実績と乖離した場合、
  過去に「効かない」と判定した案件の再判定アラートを出す
```

**この機能は初年度には価値を生まない。**3年目以降に「過去の判断がもう成立していない」と言える会社が他にないという状態を作ることで、解約理由を減らす。営業では前面に出さず、設計としては外さない。

| 外部依存による遅延 | ライセンス・データ入手が想定より重い | フェーズ0の並行実行で早期に可視化 |
| **乖離分解が機能不全に陥るリスク(新設)** | C-3が否と判定された場合、M4が退化し製品の中核が消える | フェーズ0最優先で検証。否の場合は構想全体を再検討する撤退基準として扱う |
| 買い手層の難度(新設) | DecisionRecordの導入には財務・経営企画・事業部決裁ラインへの営業が必要で、開示担当への営業より難度・サイクルとも重い。個人構築(C2)との相性は率直に言って良くない | 入口はサステナビリティ/IR(SSBJ予算)のまま据え置き、Q3(投資判断)で自然に財務側へ染み出す設計とすることで初期の営業難度を抑える |
| 効率化ツールへの転落 | M5だけが使われM6/M7が使われない | フェーズ1末の判断基準で早期判定。M6のDecisionRecordが実際の決定に接続された事例の有無を基準とする |
| 単一標準への収斂 | S3が単一手法を確定させ変換需要が消滅 | 標準確定後は「旧手法での過年度再計算・遡及適用」への製品定義の転換で対応(TCFD→ISSB移行時の前例と同型) |

### 11.4 追加性に関する自己点検 ※v1から一部改訂

εは入口(開示・情報提供)ではレバレッジが低い。追加性は**M6(DecisionRecordが実際の決定に接続されること)**によってのみ回収される。

したがって、収益が出ていても以下は独立に評価する:

> **DecisionRecordの★判定が実際の稟議・投資判断の結論を1件も変えていなければ、εは情報提供層に留まったことになり、終端目標(生態系サービスへのインセンティブ構造の修復)に届いていない。**

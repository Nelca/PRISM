# ADR-0004: 算定対象拡大の順序とカテゴリ境界

**日付:** 2026-08-28
**種別:** 設計判断(非GATE)
**状態:** 採用
**関連:** `docs/roadmap/category-expansion-directive.md`、`docs/data/category-expansion-acquisition.md`、`docs/decisions/0001-mvp-pilot-category-scope.md`

---

## 論点

PRISMは気候(GHG)と水の算定・貨幣化まで対応している。次に追加する対象について、開示上の重複度だけでなく、未内部化コストの可視化、係数と物理データの取得可能性、既存実装への接続を踏まえて実装順序を固定する必要がある。

あわせて、次の点を曖昧なまま実装すると、後から全レコードの再解釈が必要になる。

- 「汚染」の最初の入力を、PRTR対象化学物質とNOx/SOx/VOC等のどちらにするか
- 廃棄物を対象外のままにするか
- 土地利用を外部係数の契約完了まで待つか
- PRTRの移動量と廃棄物処理量を同じ費用として二重計上しないか

## 決定

### 1. 最初の追加対象はPRTR対象有害化学物質

汚染MVPの最初の入力経路は、**PRTR対象化学物質の事業所別・物質別・排出媒体別排出量**とする。NOx/SOx/VOC等の大気汚染物質は後続拡張とする。

ただし「PRTR対象であること」と「貨幣化係数が存在すること」は同義ではない。全対象物質を自動的にLIME3へ名称一致させず、年度別PRTR物質コードからLIME3基本フローコードへのレビュー済み対応表を経由する。対応できない物質はゼロや類似物質で補完せず、`unmapped`として未算定量を表示する。

### 2. 廃棄物は汚染拡大リリースの後半に含める

廃棄物は対象外とせず、PRTR汚染MVPの後続フェーズに組み込む。ただし、**リリース単位は同じでも算定カテゴリは分ける。**

- 汚染: 物質 × 排出媒体 × 直接環境排出量
- 廃棄物: 廃棄物種類 × 処理経路 × 発生/処理量

PRTRの「下水道への移動量」「事業所外への移動量」は、汚染MVPでは貨幣化しない。廃棄物フェーズで処理経路データと接続してから算定し、直接排出との二重計上を防ぐ。

### 3. 土地利用はLIME3単独の内部パイロットを先行する

ESVD・IFVIの契約回答を待たず、既存のAIST-IDEA Ver.4.0標準版に含まれるLIME3基本フロー係数で土地利用・土地改変の内部パイロットを開始する。

拠点・開発案件の活動であるため、暫定的にLIME3の**「利子率2%、生産国、日本、統合化、US$」**列を使用する。元資料の手引きで別の指定が確認された場合は、係数版を更新して再計算する。この選択は前提台帳と係数メタデータに残す。

公開メッシュから変化を断定せず、顧客提供の案件ポリゴン、転換前後の土地区分、面積を一次入力とする。国土数値情報の土地利用細分メッシュはスクリーニングと照合に限る。

### 4. 外部照会は実装と並行する

- IFVI: Air Pollution、Land Use and Conversion、Waste、Water Pollution、Global Value Factor Databaseの商用条件
- CE Delft: PRTR対象有害化学物質の第2手法として、係数の商用埋込・派生結果表示条件
- ESVD: 土地利用・生態系サービス評価の商用利用、個別レコード/一括アクセス条件

書面許諾前にIFVI・CE Delft・ESVDの係数を顧客向け算定へ有効化しない。回答待ちは、LIME3による汚染・廃棄物・土地利用の内部実装を止める理由にはしない。

### 5. 送粉は保留する

食品・農業の具体顧客、対象作物、農地ポリゴン、収量/作付データが揃うまで実装しない。汎用カテゴリとして先に作らない。

## 理由

| 判断 | 理由 |
|---|---|
| PRTRを先行 | 対象物質・事業所・年度・排出媒体が公的制度で識別され、顧客保有データとの照合も可能。未内部化された直接排出の社会的費用を設備投資判断へ接続しやすい |
| 廃棄物を後半へ | 物理データは得やすく、TNFD/ESRS上も対象。ただし処理費用と外部費用、PRTR移動量の重複を先に整理する必要がある |
| 土地をLIME3で先行 | 既存ライセンスと抽出済み係数があり、ESVD/IFVIの交渉待ちを内部検証の待ち時間にしない |
| 送粉を保留 | 実装可能性より対象顧客と入力データの有無が律速で、現時点では汎用化の根拠がない |

## 実装への含意

1. `PhysicalQuantityInput`の`category + quantity + unit`だけでは不足する。物質、媒体、PRTR年度、廃棄物処理経路、土地転換前後を識別できる判別可能な入力型へ拡張する。
2. 外部係数を`Record<string, number>`だけで渡さない。手法版、フローID、単位、通貨、価格年、地理視点、ライセンス状態、原本ハッシュを持つ係数レコードを導入する。
3. PRTR名称とLIME3名称のあいまい一致を本番計算に使わない。確定対応表のみを計算対象にする。
4. LIME3統合値は複数AoPを含みうる。内訳を金額に復元できない対象は、単一AoPへ誤って割り当てず`unmapped`として扱う。
5. 顧客向け結果には、投入量・算定できた量・未対応量・対象外移動量を並記する。

## 既存ADRとの関係

ADR-0001の「気候と水の両方でMVP実データ検証を行う」は維持する。本ADRはそのMVPを置き換えず、追加カテゴリの実装順序を定める。

# PRISM UI/UX修正指示書 第3版(ユーザーストーリー整合)

**作成日:** 2026-08-16
**位置づけ:** 第1版(画面統合・用語・導線)・第2版(ディテール改善)の後続。ユーザーからの指摘「評価対象の絞り込みで何をすれば良いのか分からない」「感応度が高い拠点は見るだけで終わる」「詳細評価に切り替えた後に何をすべきか分からない」に基づく、**ユーザーストーリー整合**の修正指示。

## §0 総評と設計原則

各画面が「データの表示」で終わっており、**見る → 解釈する → 操作する → 次へ進む**というストーリーの後半が欠けている。象徴が②の「感応度が高い拠点」表:操作がなく、解釈の手がかりもなく、隣の「評価対象の一覧」と行がほぼ重複する、純粋な「見るだけの表」になっている。また操作(詳細評価への切替)をしても、画面は行の背景色が変わるだけで、「操作が成功したこと」も「その結果どこで何が見られるようになったか」も伝えない。

本指示書の原則:

> **すべての表示ブロックは、(a)なぜ見るのか(b)どう解釈するのか(c)次に何をするのか、の少なくとも1つに明確に答える。答えられないブロックは、答えられるブロックに統合するか削除する。すべての操作は、成功の確認と「次はどこで何が起きるか」をその場で返す。**

## C-01 【P0】②の2表を1表に統合し、「見るだけの表」をなくす

- **現状:** 「感応度が高い拠点」表は (1)操作がない、(2)解釈の説明がない、(3)下の「評価対象の一覧」と行がほぼ重複(感応度は一覧の内訳4項目の1つ)。第1版指示02で/sitesから移設した際に「絞り込みの入力」と位置づけたが、実際には入力として機能しておらず、初見ユーザーには「これで何をするのか」が分からない。
- **修正:**
  1. **「感応度が高い拠点」カードを削除**し、「評価対象の一覧」をこの画面の唯一の表にする。
  2. 削除に伴い失われる情報を一覧側に吸収する:
     - 感応度セルに、バーに加えて**分数表示(例: 2/4)と未評価注記**(現在は削除予定の表とtitleにしかない)を小書きで表示。`sensitivityFraction`/`unevaluatedCriteriaNote` を流用。
     - **除外課題**(座標未解決。`priorityScores` に現れない `materialIssues` の `excluded` 行)を一覧の末尾に「対象外」行として追加する(「黙って消えない」原則の維持。現状は削除予定の表にしか出ていない)。優先度・内訳セルは「—」、理由列に除外理由。
  3. 感応度の**解釈**を与える: 表のfootまたはガイドに「感応度が高い拠点は自然への依存・影響が強く、財務影響が生じやすい評価候補です」という一文を追加(TNFD 5基準の定義文は既存のtitleに残す)。
- **対象:** `app/assessment/page.tsx`

## C-02 【P0】切替操作に「成功の確認」と「次」をその場で返す

- **現状:** 「詳細評価」に切り替えても、再レンダリングで行の背景色が変わるだけ。操作が効いたのか、その結果どこで何が見られるのかが分からない。
- **修正:**
  1. `setDepthOverrideAction` の戻り値(FormState)に成功情報を追加し、`DepthToggle` が切替成功後にインライン確認を表示する:「詳細評価に切り替えました。算定結果は**価値の算定と代表値の選択**で確認できます →」(/valuationへのリンク付き。概算評価へ戻した場合は「概算評価に戻しました。この課題は価値の算定の対象から外れます」)。
  2. 表示位置は行内(理由列の下か、切替コントロール直下)で、次の操作をすると消えてよい。エラー表示は既存どおり。
- **対象:** `app/assessment/actions.ts`、`app/assessment/depth-toggle.tsx`

## C-03 【P0】StepNavを「状態連動の次にやることバー」に拡張する(全画面)

- **現状:** 各画面末尾のStepNavは固定の前後リンクのみ。「この画面でやり残していること」「次のステップで何が待っているか」を伝えない。ホームには `deriveOpenTasks` によるタスク一覧があるが、各画面に出ないため、画面の中にいるユーザーには届かない。
- **修正:** `StepNav` を拡張し、サーバー側で導出した状態を受け取って表示する:
  1. **この画面の残タスク:** `deriveOpenTasks(result)` のうち `task.href === current` のものを「この画面でやること」として前後リンクの上に表示(文言・リンクはopen-tasksのものを流用)。ゼロ件なら「この画面での操作は完了しています」を小さく表示。
  2. **文脈付きの次リンク:** 固定の「次:◯◯ →」に実データの文脈を1行添える。例: ②なら「詳細評価に指定した◯件の算定結果を確認します」(◯は `deriveStepProgress` または結果から導出)。各画面1文でよい。次ステップに残タスクがある場合はそれを優先して添えてもよい。
  3. 実装は各page.tsxが既に持っている `result` を `StepNav` にpropsで渡す形とし、**open-tasksの導出を二重実装しない**。ホームの「次にやること」と同一ソースを保つ。
- **対象:** `app/components/step-nav.tsx`、全6画面のpage.tsx、(必要なら)`lib/pipeline/open-tasks.ts` に画面別の文脈文を導出する小関数を追加

## C-04 【P1】ガイドを「仕組みの説明」から「使い方の手順」に書き直す(全画面)

- **現状:** 各画面のGuideBoxは仕組みの説明(「〜から優先順位を算定します」)で、**操作の順序**を語っていない。初見ユーザーの「結局何をすればいいのか」に答えていない。
- **修正:** 全6画面のガイド文を「番号付きの短い手順+解釈の一文」に書き直す。例(②):
  > この画面では詳細評価に進める課題を決めます。**1.** 優先度(4項目の合成順位)を確認 → **2.** 詳細評価する課題を切り替えで指定 → **3.** 次の「価値の算定」へ。優先度が上位の課題が自動で詳細評価になっていますが、手動で変更できます(変更は記録に残ります)。
  他画面も同じ型で、そのページで実際にできる操作に即して書く(実装を読んでから書くこと)。既存の規律文(「推奨値は表示されません」等、第1版§5に関わるもの)は残す。
- **対象:** 全6画面のpage.tsxのGuideBox文面

## C-05 【P1】③の課題横断の残作業を見えるようにする

- **現状:** ③で課題が複数ある場合(課題切替ピル)、片方の課題で代表値を選んでも、もう片方が未選択のままであることに気づけない。
- **修正:**
  1. 課題切替ピルに、代表値未選択の課題へ**小さなドット**(ナビの要対応ドットと同じ意匠)を表示。
  2. 代表値の選択カードの直下に、他課題が未選択の場合「課題◯◯の代表値がまだ選ばれていません →」のリンクを表示。
  3. C-03の残タスク表示と整合させる(同じ状態から導出)。
- **対象:** `app/valuation/page.tsx`

## C-06 【P2】⑤の操作順を明示する(承認基準が未入力のとき)

- **現状:** 判定が保留(承認閾値未入力)のとき、小さなnoteと`headExtra`のフォームボタンがあるだけで、「この画面の最初の仕事は閾値の入力」であることが伝わらない。
- **修正:** verdict=pending の拠点では、判定結果カードの本文先頭に「まず投資判断の承認基準(閾値)を入力してください(財務・経営企画部門への確認が必要です)」+入力フォームを開く主要ボタン(pill-btn--primary)を置く。入力済みの拠点では現状表示のまま。
- **対象:** `app/decision/page.tsx`

## 実施順序と検証

単一波で実施(C-01〜03が同一画面で相互依存、C-03は全画面+open-tasks連携のため分割の利益がない)。順序は C-01 → C-02 → C-03 → C-04 → C-05 → C-06。

- 完了条件: `npm run typecheck` / `npm run lint` / `npm test` 全通過。
- devサーバーが起動中の場合は停止・再起動せず、GETのcurlで (1)②の表が1つになり除外行が末尾にあること、(2)StepNavに残タスク/完了表示が出ること、を確認。
- **受け入れ基準(第3版):** ②を初めて開いたユーザーが、ガイドと画面だけで「優先度を見る → 詳細評価を指定する → 次へ進む」を迷わず実行でき、切替の直後に「何が起き、次にどこへ行くか」が画面に明示されること。「見るだけで何にも使われない表」が全画面に存在しないこと。

# LP 訴求・コンバージョンレビュー

改訂：2026-10-05。初見のサステナビリティ推進・経営企画・財務担当者を想定。

## 読者に伝える約束

環境課題が自社の費用や収支に与える影響を試算し、対応が必要かを社内の基準で確認する。算出した数字だけでなく、その数字を採用する理由を説明する材料が得られる。

対象は、環境データや評価結果を既に持ち、社内説明・対応方針・投資の検討に使いたい担当者。環境データの収集だけを求める人に、全用途を満たすと訴求しない。既定のブランドコピー３点は維持した。

## 初見で伝わりにくかった点と変更

| 問題 | 修正 | 狙い |
|---|---|---|
| 冒頭が「算定・評価・判定」という機能分類 | 費用・収支への影響を確かめるという説明に | 製品カテゴリを知らなくても用途が分かる |
| 評価額の差を説明するが、読者の困りごとが弱い | 会議にどの金額を出すか、採用理由を説明できるかという問い | 日々の社内説明と結び付ける |
| 理解前にNPVのグラフを提示 | 機能説明を具体例より先へ | 概要から実例へ順に理解できる |
| 「前提」「基準をまたぐ」だけでは意味が曖昧 | 計算に使う条件、赤字にも黒字にもなる等に | 専門家以外も結果を読み取れる |
| 機能を操作として紹介 | 影響を金額で把握、対応の必要性を確認、判断理由を説明 | 読者が得る業務上の価値を示す |
| 主な入口が体験、最後のボタンが整理シート | 概要PDFを主CTAとして冒頭と下部に配置 | 関心が生まれた時点で社内検討へ進める |
| 取得物と必要な入力が不明 | A4・1枚、内容、メールアドレス入力不要を明記 | クリック後の不確実性を減らす |
| 「デザインパートナー」が初見には不明 | 実際の業務で役立つかを確かめる検証段階とFAQで説明 | 提供段階と次の手順を理解できる |

資料は既存のサービス概要PDF。記載している機能・活用場面・検証の進め方を確認し、取得物以上の成果物や無料相談は約束しない。節水設備は説明用の例に限定する。

## CVR 10%の定義

10%は目標であり、予測値・改善実績・保証ではない。現状は外部解析サービスも相談フォームも接続していないため、CVRの実績は未計測。

最初の指標を「概要資料の取得操作率」とする。

- 分母：公開LPへの有効な訪問セッション数。
- 分子：同一セッション内で概要PDFの保存ボタンを１回以上押したセッション数。
- 目標：分子÷分母が10%。複数回クリックは１回として数える。
- 除外：運営者の確認、テスト、ボット。流入元別・端末別にも分ける。
- これは資料を保存し終えた人数や、商談につながるリード数ではない。

相談窓口の接続後は、フォームの実際の送信成功または予約完了を別のCVとして計測する。窓口へのクリックを相談完了として扱わない。取得操作率が上がっても、相談の質・適合案件が増えたかを別途確認する。

## 計測準備

冒頭・下部のPDFボタンに識別子を付与し、クリック時に `prism:cta` イベントを発火する。`detail.action` は `overview_download_click`、`detail.placement` は `hero-overview` / `bottom-overview`。イベントはブラウザ内のみで、個人情報・Cookie・外部送信・保存を伴わない。公開時に選んだ解析基盤で、ページ訪問、セッションの重複排除、ボタンクリックを接続する必要がある。このフックだけではCVRを算出できない。

## 公開後に確認する順序

1. 想定担当者にLPを読んでもらい、「何ができるか」「何を用意するか」「資料に何が載っているか」を自分の言葉で説明してもらう。詰まる語句を先に直す。
2. 資料の取得操作を端末別に確認し、解析側に重複や欠測がないかを点検する。
3. 紹介・検索・広告を混ぜて評価せず、対象者に近い流入ごとに基準値を取る。分母の小さい短期間の10%到達を勝利と判定しない。
4. 冒頭の補足説明を、現行の「費用・収支への影響」と「社内説明の根拠」の２案で検証する。承認済みの主コピーは固定。CTAや配信条件を同時に変えず、検証対象を絞る。
5. 必要なサンプル数と期間は、基準CVRと検出したい差から事前に決める。日々の数字を見て都合のよい時点で終了しない。資料取得後の用途や相談につながった理由も合わせて判断する。

未検証の導入社数、効果率、顧客推薦、期限・先着枠を追加していない。強い訴求の根拠として、製品ができること、具体例、取得できる資料を使う。

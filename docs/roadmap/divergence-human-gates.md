## 4. H-04 実利用者の業務価値確認(T-19)

### 4.1 検証シナリオ

M4「乖離原因分解」の業務価値を、想定利用者3類型がそれぞれの意思決定文脈で確認するための検証シナリオ。実行時間目安は15〜30分/利用者。

**対象ユースケース:** 本社工場(site-042)、取水 45,000 m³/年(デモ既定値)、同一比較対象の代替費用法・LIME3・IFVI 4内訳を並べた既定ケース。現行値(作業台帳 §2、旧エンジン時点): 代替費用法 27,900,000 円 / LIME3 水 57,761 円 / IFVI VFes 12,624,579 円 / IFVI VFnutrition・VFdisease・VFaccess は公表 0(0 円)。

| 利用者 | 職務 | 意思決定の問い | シナリオ(現行A → 完成版B) |
|---|---|---|---|
| **パターン1** | サステナビリティ担当 | 「この拠点のリスク評価値を、どの手法で代表値として使うか」「評価手法のばらつきが本質的か、データ/前提が違うだけか」 | A: 金額の並記(上記の現行値と倍率のみ) → B: 原因分解「なぜ違うのか」(被覆経路 / 価値評価技法 / 地理較正 / 時間モデル / 基礎モデルの分別、数値化できた寄与と数値化できない既知差異の併記、ゼロ値の意味) |
| **パターン2** | 経理・経営企画 | 「この評価を投資判断に組み込むなら、どのシナリオを想定すべきか」「ばらつきが大きければ、追加調査の対象費用はいくらか」 | A: 単純な代表値選択か複数シナリオ並記 → B: 「追加データ X を取得すれば比較可能性が高まる」「残る差異 Y は価値評価技法の選択によるもので、精度の問題ではない」という判定材料が記録される(推奨はしない) |
| **パターン3** | 監査・保証 | 「この評価は再現可能か」「推定値がどこに入り込んでいるか」「手法間の違いが公式な根拠から説明できるか」 | A: 計算過程がブラックボックス → B: 「反実仮想値 v(S) / 寄与 φ / 残差 R・根拠・版・ハッシュ」まで全件ドリルダウン可能。各要因の差し替え式、固定した設定、出典まで追跡可能 |

### 5.2 M4 固有の論点: 派生結果の再配布性

M4の出力(反実仮想値・寄与・残差・比較レシピトレース内の係数リテラル)が、各ライセンス規約の「派生結果」「再配布」「公開報告」条項に当たるかを確認する。

#### 5.2.1 通常の派生結果と M4 派生結果の区別

| 操作 | 派生結果と見なす? | ライセンス上の扱い |
|---|---|---|
| LIME3 の係数値(US$/m³)をそのまま表示・出力 | いいえ | データベースの一部の複製提供に当たり得るため、出力 API では省略(licensing.md LIME3 節) |
| 手法間の倍率・金額差(計算結果)を表示 | はい | 派生結果。係数そのものではないが、各規約の「派生結果」条項の書面確認が必要 |
| 反実仮想値 v(S)・寄与・残差を表示 | はい | 派生結果。トレース内の係数リテラルは表示対象から除く |
| 「[監査] 入力 / 式 / 反実値 / 出典 / 版 / ハッシュ」をエクスポート | **やや問題** | 「式」に係数値そのものが含まれる場合、再配布判定が分かれる可能性。API出力では省略(§5.2.2) |

#### 5.2.2 出力APIでの設計方針

`lib/pipeline/public-result.ts` の方針(T-14 で実装。本書作成時点では未実装):

- **顧客向け結果API:** 反実仮想値・寄与・残差・比較レシピのメタデータ(版・ハッシュ・根拠資料の引用)のみを返す。係数の生値は**省略**
- **監査エクスポート(内部用):** トレース内の計算式・係数値を完全記録。書面許諾を得るまで本番顧客へ非表示
- **帰属表示:** 用いた各データ・手法について、ライセンス状態(`productionDisplayAllowed`)を読込み、許諾済みのものだけを表示

各ライセンス規約の回答に基づき、下表の分類を確定する。

| ライセンス | 派生結果API出力の可否 | 内部監査ログの保存 | 判定根拠 |
|---|---|---|---|
| LIME3 | **可**(係数値は省略) | 可 | 「製品への組込は可能」(既存社内ライセンス), 再配布は「生ファイル・元データ」に限定 → 派生結果は該当外と解釈 |
| IFVI(許諾待ち) | **書面確認後に判定** | 書面確認後 | 「製品販売・派生結果表示」が§1.3(a)に該当するか次第(H-03) |
| WDPA・ESVD・CE Delft | **不可(許諾待ち)** | 不可 | 商用契約決定まで本番利用は禁止。内部評価用のみ可 |

### 5.3 ライセンス状態の扱い(コード実装)

#### 5.3.1 MethodOutput / ValuationRecord のライセンスメタデータ

各計算結果には `licenseMode` フィールドを持たせ、3状態を区別:

```typescript
type LicenseMode = 
  | "commercial_approved"      // 書面許諾済み、本番出力可
  | "pending_review"           // 許諾待ち、本番結果へ出さない
  | "reference_only"           // 参考値のみ、公開報告不可
  | "internal_evaluation"      // 内部評価限定
```

**実装ルール:**
- `licenseMode: "pending_review"` のレコードは、結果テーブルに保存されるが、本番顧客へのAPI・画面・PDF・CSV エクスポートでは**行ごと非表示**
- `productionDisplayAllowed: false` が対応属性として M3プラグイン側に存在(既実装、`monetization/plugins/*.ts`)
- 許諾状態が変わる(H-03回答後)たびに、該当プラグインの `productionDisplayAllowed` を切り替える**だけで、再計算不要**(計算結果は既に保存済み)

#### 5.3.2 失効・更新への対応

LIME3のようにライセンス有効期限を持つデータについて:

- **有効期限:** 2027-06-30(LIME3の場合、`docs/data/licensing.md` §5に記載)
- **更新責任者:** 契約窓口(AIST-IDEA ユーザー管理部門)
- **抑止方法:** `build-valuation-records.ts` で、各プラグインの `methodVersion` がライセンス有効期限内の版かを確認。期限切れの場合は警告ログを出し、新しいrunでは該当手法を skip
- 旧runの結果は保持(監査証跡用)、新runでは該当手法のみ欠落。全体結果は失効によって「incomplete」フラグを立てる

#### 5.3.3 開示・報告での扱い

顧客が M4 結果を TCFD / SSBJ 開示へ引用する場合:

- **許諾済み手法のみ:** 「本分析では X 手法を採用しました」と記載可
- **許諾待ち手法:** 「参考値として分析対象に含めていますが、商用開示根拠としては不採用」と明記
- **失効手法:** 「[参考] 過去の分析では Y を使用していましたが、現在のライセンス有効範囲外のため新分析では採用していません」と過去実績として注記

| **必要期限** | 主実証に第2手法(LIME3以外)を本番有効化する前。目安は主実証 E 段階終了～F段階開始(2026年10月末〜11月初)

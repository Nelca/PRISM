# モバイル(Claude iPhoneアプリ)からの作業継続ガイド

**対象読者:** Claude Codeでのローカル作業ができない間、iPhoneのClaudeアプリ(GitHub連携)から本リポジトリを参照して作業を継続する場合。人・AIどちらが読んでも良い。
**前提:** 別アカウントのClaude.aiプロジェクト(要件定義・価格検討を行っている)からも、GitHub連携で本リポジトリを参照できる。本ガイドはそちらの作業にも適用される。
**最終更新:** 2026-08-11

---

## 0. まず何を読むか

読む順序そのものは `docs/README.md` の「読む順序」に従う(ここでは重複させない)。**本ガイドはその手前に読む、モバイル作業固有の制約と、今すぐ拾える次のタスクだけを追加するもの。**

---

## 1. この環境でできること・できないこと

Claude iPhoneアプリ(GitHub連携、コード実行環境なし)を前提に作業する。

| できる | できない |
|---|---|
| リポジトリのファイル読み取り、設計・要件についての議論 | `npm test` / `tsc --noEmit` / `npm run dev` などの実行 |
| `docs/` 配下の追記・修正案の作成 | ローカルDB(Postgres)への接続、UIの実際の動作確認 |
| コードを読んだ上でのレビュー・設計相談・次タスクの優先順位付け | コード変更が実際にテスト・型検査を通ることの確認 |

**したがって:**

- **コード変更(`packages/core/`・`app/`・`lib/`)を提案・コミットする場合は、「検証済み」ではなく「提案」であることを明記する。** コミットメッセージまたはPR descriptionに「⚠️ Claude Codeでのtsc/vitest未実施」のように残し、次のClaude Codeセッションでどのコミットが未検証か一目でわかるようにする。
- ドキュメント(`docs/decisions/`・`docs/requirements/`等)のみの追記・修正は、実行を伴わないため通常のワークフローと同様に進めてよい。
- 新しい設計判断を`design-rationale-log.md`にD-番号で記録する場合は、末尾の既存番号の続きにする(本ガイド作成時点の最新は **D-125**)。

## 3. 別アカウントの要件定義・価格検討プロジェクトとの接続

そちらの成果物(価格モデル・要件変更等)をこのリポジトリに反映する際の置き場所の目安:

- 事業側の資料 → `docs/business/`(既存: `board-proposal.md`・`outreach-action-plan.md`)
- 設計に影響する決定 → `docs/decisions/design-rationale-log.md` にD-番号で追記(仕様自体を変える場合は該当 `docs/requirements/m*.md` も更新する)
- まだ実装に落とせない検討中の事項は、このリポジトリに書かず、そちら側のプロジェクトに置いたままでよい。実装判断が固まってから持ち込む

---

## 4. Claude Codeに戻ったときの確認事項

- `git log` で不在中のコミットを確認し、「⚠️ 未検証」マーカーの付いたコミットがあれば `tsc --noEmit` / `npm test` / `npm run lint` を実行する
- ドキュメントのみの変更は検証不要
- 本ガイド自体は一時的な運用文書。次回の長期不在時にも使えるよう内容を残してよいが、`docs/README.md`の構成・権威性の表とは重複させない

## 0. 最重要未検証事項 — 後続作業はここを参照すること

### 0.1 フェーズ0 C-3 の検証内容を再定義する

構想書10.2節では、フェーズ0の技術検証を「IFVI・CE Delft・LIME3のエンドポイント被覆/割引率/価値概念のメタデータが**機械可読または手作業で抽出可能か**」と定義している。

**この定義では不足している。** 本モジュールの設計を詰めた結果、実装に必要な条件は次の2段階であることが判明した。

| 段階 | 検証内容 | 現行C-3での扱い |
|---|---|---|
| **C-3a** | 各手法のメタデータ(価値概念/エンドポイント被覆/割引率/地理較正)が抽出可能か | 定義済み |
| **C-3b** | **抽出したメタデータを、手法横断の共通語彙に対応付けられるか** | **未定義。これが実装の真の前提** |
| **C-3c** | **各要因を差し替えた反実仮想の再計算が可能か**(§5.4参照) | **未定義。抽出できても再計算できなければ分解できない** |

**C-3aを通過してもC-3b・C-3cで詰まれば、M4は実装できない。** フェーズ0の検証設計を上記3段階に組み替えること。

### 0.2 C-3bが困難な理由 — AoP(保護対象領域)に共通体系が存在しない

依存側の生態系サービス分類には CICES という共通体系が存在するが、**影響側の損害到達先(AoP)には共通体系がなく、手法ごとに独自の分類を使っている。**

**具体的な難所(解消済み・履歴として記録):**

- LIME3 の「一次生産」は、資源可用性とも生態系品質とも解釈でき、機械的な変換規則が存在しなかったが、一次資料の確認により`resource_availability`と確定した(自然の光合成による生産力という定義から)
- CE Delft の「建造物・材料」は標準的な4分類のいずれにも素直に収まらない。**これは未解消のまま(MVP水パイロットのスコープ外)**

この対応付けは**判断を伴う**。したがって:

1. 対応表そのものが AssumptionEntry の対象(誰がいつ、どの根拠で対応付けたか)
2. 対応表を後から変更すると、過去の分解結果が変わる(再計算ハッシュに影響)
3. 一部は「**対応付け不能**」として残す設計にする(§5.4の「推定で埋めない」原則の適用)

**AoP だけでは被覆一致を判定できない反例:** IFVI VFnutrition(栄養不良経路)と VFdisease(水系感染症経路)は、どちらも `aopCode: "human_health"` として正規化されるが、**異なる因果経路・健康損害メカニズム・被害統計を前提としている。** AoP コードの一致だけでなく、経路・エンドポイント・測定指標の細粒度まで確認しなければ同一被覆と判定してはならない。これは§5.2 の因果経路階層を明示する理由である。

## 2. 入力

```
対象: 同一の物理量 × 同一地点 に対する ValuationRecord 群(N ≧ 2)
      各レコードは手法ID(版番号付き)と手法メタデータを持つ
```

**2026-08-01追記(M3要件定義との整合):** 1つの外部手法が複数のValuationRecordを生成しうる(M3 D-1、IFVI Water Consumptionは4本の内訳値 VFnutrition/VFdisease/VFes/VFaccess に分解して取り込まれる)。したがって「N=手法の数」ではなく「**N=ValuationRecordの数**」であることに注意する。methodIdは分解元が追跡できるよう `{親手法ID}.{内訳ID}`(例:`ifvi-water-consumption.VFnutrition`)の形式を用いる。

### 2.1 比較手法数の上限

**上限 N = 5(ユーザーが選択)。**

制限の根拠は計算量ではなく、**出力の可読性と監査説明の単位**である。

- 計算量: N=5 で全ペア C(5,2)=10 ペア × 3要因の部分集合 2³=8 通り。中心値のみで60回程度の再計算であり、負荷にならない(N=10でも45ペア=270回)
- 可読性: 10ペアの分解結果を並べても、稟議でも監査でも読めない
- 実態: N=5でも §3 の価値概念分割により、各グループは2〜3手法に落ちるのが通常で、実質のペア数は3前後になる

**2026-08-01追記(上限の適用単位を明確化):** N≤5は**価値概念で分割した後(§3段階1)の各グループ内**に適用する。分割前の総数には適用しない。

理由:MVPの水パイロットでは、IFVIの分解(4本)+LIME3(1本)+代替費用法(1本)で合計6本のValuationRecordが生成され、分割前の総数はN=5を超える。しかし段階1の価値概念分割により、交換価値グループ(VFaccess・代替費用法の2本)と厚生価値グループ(VFnutrition・VFdisease・VFes・LIME3の4本)に自然に分かれ、各グループはN≤5に収まる。D-12の可読性という制限の趣旨は、そもそも同一グループ内でのペア比較の読みやすさを指しており、価値概念をまたぐグループ間は最初から比較しない(段階1で「比較不能」とラベル)ため、グループ単位で数えるのが元の趣旨に合致する。

**改訂(2026-09-06):** 上限を超えた場合の取扱を変更。手法間比較(親手法数 ≤ 5)と同一手法の内訳分析(例:IFVI VFnutrition/VFdisease/VFes/VFaccess の4内訳相互比較)は**別の分析単位**として扱う。超過ペアは例外を送出するのではなく、結果に `group_limit_exceeded` というコードを付与して保持し、パイプライン全体を停止させない。

**表示設計:** フットボールチャートを主表示とし、ペア分解はドリルダウンに置く。

## 3. 処理 — 2段構え(構想書8.2 の規律に従う)

構想書8.2は「交換価値と厚生価値は足せない。異なる概念の合算をシステムが物理的に禁止する」と定めている。

Shapley分解は定義上「手法Aの価値概念 × 手法Bのエンドポイント被覆」という混成体の値を計算することを要求するため、**価値概念を分解要因に含めると、8.2の規律を分解エンジン自身が破ることになる。**

したがって次の2段構えとする。

```
段階1: 価値概念で分割(partition)する。分解しない
       → 「これらは異なる問いに答えている」という事実の提示のみ
       → 価値概念をまたぐ差は「比較不能(incommensurable)」とラベルし、
          倍率を機械的に算出しない
       → 地理較正も含め、グループ間では一切分解しない(規律を単純に保つため)

段階2: 同一価値概念グループ内で、残り3要因のShapley分解を実行
       → エンドポイント被覆 / 割引率 / 地理較正
```

### 3.1 「価値概念の寄与」をどう扱うか

構想書0章は「何倍が問いの違いか」を謳っているが、これは**残差(residual)として提示する**。3要因で説明できた分を除いた未説明乖離として示し、価値概念が異なる場合はその残差が問いの違いに支配されている、という**記述**にとどめる。断定的に「価値概念の寄与 = ◯倍」とは出力しない。

これは構想書8.5の3層構造(層iii = スコープ・方法論不確実性は「数値に混ぜず、除外事項リストとして別枠で出力」)と整合する。残差を正式な分解項目として扱うことには成長会計(ソロー残差)・Oaxaca-Blinder分解という確立した先例がある(§8)。

### 3.2 再グループ化の判定基準

同一グループとみなす条件:

1. 価値概念が完全一致(必須)
2. エンドポイント被覆が一致(§6.3 の一致階層設定に従う)

**2026-08-01追記:`aopCode: "not_applicable"`同士の扱い。** 代替費用モデル等、エンドポイント被覆モデルを用いない手法(M3 D-1のVFaccess、代替費用法)は`aopCode`が`not_applicable`になる(M4要件定義書§6.2の正規化コードには存在しない、AoP体系の対象外を示す値。`docs/data/aop-mapping-v1.md` §3参照)。**この場合、`not_applicable`同士は条件2(エンドポイント被覆が一致)を満たすものとして扱い、グループ化・比較の対象とする。** 理由:いずれも「エンドポイントモデルを用いない直接コスト」という共通の性質を持ち、比較すること自体に意味があるため(例:IFVIのVFaccessとPRISM自身の代替費用法は、どちらも「将来/現在の代替調達コスト」という同種の問いに答えている)。

## 4. 分解アルゴリズム — 対数空間 Shapley

### 4.1 なぜ対数空間か

構想書0章が求めているのは「その差のうち**何倍が**価値概念の違いで、何倍がエンドポイント被覆の違いか」という**乗法的分解**である。手法間の差が2桁で出る対象に加法分解を当てると、寄与額の大小が水準に引きずられて解釈不能になる。

```
ln V_A − ln V_B = c₁ + c₂ + c₃              (Shapley寄与、対数空間)
V_A / V_B       = exp(c₁) × exp(c₂) × exp(c₃)
```

残差なしの厳密な乗法分解が成立する。

### 4.2 Shapley寄与の算出

要因集合 F = { endpointCoverage, discountRate, geographicCalibration }(k=3)。

手法Bを基準、手法Aを対象とし、部分集合 S ⊆ F に対して「S に含まれる要因だけを B の設定から A の設定に差し替えて再計算した値」を v(S) と定義する。v(∅) = V_B、v(F) = V_A。

```
c_i = Σ_{S ⊆ F\{i}}  [ |S|! (k−|S|−1)! / k! ] × ( ln v(S ∪ {i}) − ln v(S) )
```

k=3 なら評価が必要な部分集合は 2³ = 8 通り(うち2つは既存の V_A・V_B なので新規計算は6回)。全6順列分の平均が上式で厳密に得られる。

**改訂(2026-09-06):** 現行実装(2026-08)は、手法Bの値へ独立な倍率を掛け合わせて v(S) を作っており、要因ごとの差し替え再計算ではなかった。完成実装では、版管理された比較レシピと計算トレースから反実仮想評価器を実行して各 v(S) を得る。この変更に伴い、次の要件を追加する。

- **順列展開ではなく部分集合の重み付き和:** Shapley寄与を全順列の展開ではなく上式で計算し、対数空間で符号付きの相互作用を保持する。メモ化により同じ S を再評価しない。
- **評価回数の予算:** §6.2に従い、1ペアあたりの手法再評価回数と監査用に保存する v(S) の件数は、比較レシピで明示的に上限を持つ。超過する場合は要因を減らして部分分解とするか停止理由を返す。

### 4.2.1 具体例(2026-08-02追記、§7.2の数値と対応)

§7.2で示すIFVI Water(V_A = 8億円)とLIME3(V_B = 3億円)の比較例を、実際に8通りの v(S) を算出して確認する。**説明を単純にするため、3要因間の相互作用がない(各要因の効果が独立に掛け合わさる)ケースを想定する。**

各要因を単独で差し替えたときの倍率が、エンドポイント被覆=×2.10、割引率=×1.15、地理較正=×1.10だったとすると、8通りの v(S) は次のようになる。

| 部分集合 S | v(S) | 計算式 |
|---|---|---|
| ∅ | 3.00億円 | = V_B |
| {エンドポイント被覆} | 6.30億円 | 3.00 × 2.10 |
| {割引率} | 3.45億円 | 3.00 × 1.15 |
| {地理較正} | 3.30億円 | 3.00 × 1.10 |
| {エンドポイント被覆, 割引率} | 7.25億円 | 3.00 × 2.10 × 1.15 |
| {エンドポイント被覆, 地理較正} | 6.93億円 | 3.00 × 2.10 × 1.10 |
| {割引率, 地理較正} | 3.80億円 | 3.00 × 1.15 × 1.10 |
| {エンドポイント被覆, 割引率, 地理較正} | 7.97億円 ≈ 8.00億円 | = V_A |

要因間の相互作用がないため、全6順列のどの順で差し替えても各要因の限界寄与は変わらず、Shapley値は単純にその要因単独の倍率と一致する(c_endpoint = ln 2.10、c_discount = ln 1.15、c_geo = ln 1.10)。**要因間に相互作用がある場合は、順列ごとに限界寄与が変わるため、6順列の平均を取る必要がある**(対称性公理の意味はここにある)。

### 4.3 満たす公理(監査時の検証対象)

| 公理 | 内容 | 監査上の意味 |
|---|---|---|
| 効率性 | Σc_i = ln V_A − ln V_B(残差ゼロ) | 説明されていない差が隠れていないことの保証 |
| 対称性 | どの要因も特権的な順序を持たない | 「なぜこの順で分解したか」の説明義務が消える |
| ゼロ寄与 | 差がない要因の寄与は必ず 0 | 無関係な要因に数字が付かない |
| 線形性 | 分解の加法性 | 複数対象の集計時の一貫性 |

**明示的に開示すべき規範的前提:** 全順列を等重みで平均するという仮定(対称性公理)は、「いずれの要因も他より根源的とはみなさない」という価値判断を含む。これは中立性の実装として説明可能であり、固定順序法が要求する「なぜこの要因を最初に置いたか」の説明よりも防御しやすい。この前提は AssumptionEntry として記録する(§9)。

## 5. フォールバック規則

対数分解は v(S) > 0 を全部分集合で要求する。以下の規則を実装必須とする。すべてのフォールバックは**出力に明示ラベルを付す**。

### F-0 事前条件チェック

全 2^k 個の v(S) を算出し、以下を判定してから分解モードを決定する。

```
1. 全て算出可能か         → 不可なら F-4
2. 符号が全て同一か        → 不一致なら F-2
3. 全て正か               → 非正を含むなら F-1
4. 極端な桁差がないか      → あれば F-3
5. 乖離が閾値以上か        → 未満なら F-8
```

### F-1 ゼロまたは負の値を含む

**条件:** いずれかの v(S) ≤ 0(かつ符号は全て同一 — 混在は F-2)

**処理:** 真正な加法 Shapley に移行する。

```
V_A − V_B = Σφ_i + R
  ここで φ_i は加法Shapley寄与(§6.2の効率性契約)
      R = V_A − V* は残差(V* = Σφ_i)
```

**改訂(2026-09-06):** 現状の「加法フォールバック」は寄与配列を返さず(空配列)、UI で「分解できなかった」と表示している。完成実装では、ゼロ・同符号負値を含む場合でも、§6.2に従い加法Shapleyで真正な因子寄与を返す。**寄与配列は空でなく、必ず m 個の要因について φ₁, φ₂, ..., φ_m を返す。** 加法残差 R は分解不能な差として明示される。

**出力:** `decompositionMode: "additive"` を付与。**倍率表示を抑止し、絶対額のみを表示する。**

**理由:** 純便益を差し引く手法では負値が生じうる。倍率の解釈が成立しないため、乗法表示を出してはならない。ただしゼロ値や負値を理由に分解を放棄するのではなく、金額差による加法分解を実施して原因寄与を示すことが利用者の理解と判断に役立つ。

### F-2 手法AとBで符号が異なる

**条件:** V_A > 0 かつ V_B < 0、またはその逆

**処理:** **分解を実行しない。**

**出力:**
```
判定: 符号乖離(sign divergence)
「手法Aはこれを費用と評価し、手法Bは便益と評価しています。
  これは大小の差ではなく、費用か便益かという定性的な不一致です。
  倍率の算出および要因分解を行いません。」
```

**理由:** 符号の不一致は倍率の差より重大な発見であり、独立した論点として扱う。負の倍率に解釈可能な意味はない。

### F-3 極端な桁差(実質ゼロ) と資料に基づく被覆外判定

**改訂(2026-09-06):** 元の本文は桁差だけから「判定: 被覆外(not covered)」と断定していたが、以下の2つの条件を分離する。

**条件A:数値安定性の診断**
```
min(v) < 10⁻⁶ × max(v)(6桁超の差)
```
この場合、対数分解の数値安定性が失われる。反実仮想計算の精度診断として `magnitudeGapRatio` を記録し、停止理由のひとつとして出力する。

**条件B:資料根拠による被覆外判定**
```
当該影響について、手法の方法論または公開データが:
  - 「対象外」「評価対象に含めない」と明示している
  - または対応するデータ・係数が存在しない
```
この場合のみ、§5.6のゼロ意味として `not_covered` を確定する。手法アダプター(M3)がこれを出典付きで判定し、M4は値の大きさから推論しない。

**処理:** 上記条件のいずれかを満たす場合、分解を実行しない。ただし停止理由コードを明確に区別する。

**出力:** 数値安定性の診断値と、資料根拠の有無を別フィールドで返す。

**理由:** 一方が実質ゼロを返すことは、「被覆外である」ことの必要条件ではあるが十分条件ではない。「10⁷倍の差」として提示するのは誤った表現であり、対数寄与が不安定になるため、数値的に分解できない。しかし「被覆外」は資料に基づく定性判定であり、数値だけからは断定できない。

**注:** H-06未承認のため、新経路では桁差による省略判定を無効化する(`f3-disabled-pending-h06`)。

### F-4 再計算不能な要因がある

**条件:** ある要因 i について、差し替え後の値が算出できない
(例:損害の時間プロファイルが非公開 → 割引率のみの差し替えが不能)

**処理:** 当該要因を要因集合から除外し、k を減らして分解する。除外した要因が担っていた差は**残差**に落ちる。

```
説明済み   ×2.31
未説明乖離  ×1.16   ← 分解できなかった差
```

**出力:** 除外した要因と、除外理由(どのデータが欠けているか)を明示する。

**設計原則 — 推定で埋めない:**

> 再計算できない要因は推定せず「分解不能」と出力する。構想書9.4の除外事項(X1〜X6)と同じ思想であり、「貨幣化しない判断を仕様として明示することが逆に信頼の証明になる」という立場を分解ロジックにも適用する。**推定値が1つ混じった時点で、分解全体の監査価値が失われる。**

要因ごとの再計算可能性の見通し:

| 要因 | 再計算可能性 | 根拠 |
|---|---|---|
| 地理較正 | **高。自前で完全に再計算可能** | 構想書8.4に補正式(PPP × 所得弾力性^η × デフレータ × 相対価格 × 面積スケーリング)があり、外部依存がない |
| 割引率 | 中。損害の時間プロファイルが公開されていれば可 | 時間分布が非公開だと差し替え不能 |
| エンドポイント被覆 | 中〜低。エンドポイント別内訳の公開が必須 | 総額のみの公開だと分解不能 |
| 価値概念 | 原理的に不能 | §3 のとおり分解対象から除外 |

### F-5 割引率が null の扱い

3通りに区別する。**この区別を実装しないと、構造的な差異と表記上の差異が混同される。**

| ケース | 条件 | 処理 |
|---|---|---|
| **F-5a** | A・B ともに割引率を持たない | 要因を落として k=2 で分解。残差は生じない(ゼロ寄与公理により正当) |
| **F-5b** | 一方が「割引しない(=0%)」と文書上明示 | 0% として扱い、通常どおり再計算する |
| **F-5c** | 一方が時間次元を持たない(年間フロー評価等) | 割引率の差し替えが定義できない → **F-4 として扱い、残差に落とす** |

### F-6 レンジ(モンテカルロ結果)の扱い

**MVP では中心値のみを分解対象とする。** レンジは M3 の出力として別途併記する。

要因別に分位点を分解する設計は本質的に別問題であり、MVP スコープ外(§10)。

### F-7 効率性公理の数値検証

```
assert( |Σc_i − (ln V_A − ln V_B)| < 1e-9 )
```

対数空間 Shapley は構成上厳密に一致するため、逸脱は実装バグを意味する。**逸脱時は結果を出力せずエラーとする**(誤った分解を出すより出さない)。

### F-8 乖離が軽微な場合

**条件:** |ln(V_A / V_B)| < ln(1.05)(差が 5% 未満)

**処理:** 分解を実行しない。

**出力:** 「有意な乖離なし」と表示。

**理由:** 分母が小さいと寄与割合が発散し、意味のない大きな百分率が表示される。

**改訂(2026-09-06):** F-3と同じく、H-06未承認のため、新経路では閾値による省略判定を無効化する(`f8-disabled-pending-h06`)。

### F-9 寄与の符号が相殺する場合(表示規則)

個々の c_i は、合計が正でも負になりうる(相殺し合う要因)。

**絶対値を取ってはならない。** 相殺の事実自体が発見である。

**表示規則:** いずれかの c_i が合計と逆符号の場合、**寄与割合(%)の表示を抑止し、倍率(exp(c_i))のみを表示する。** 割合が100%超や負値になり誤読を招くため。

### F-10 (新) ゼロ値の意味と付与主体

数値0と別に、以下の6区分を区別する必須条件の追加(2026-09-06)。

| 区分 | 定義 | 例 | 付与者 |
|---|---|---|---|
| `published_zero` | 出典が0と公表 | IFVI日本 VFnutrition の公表値 0.00 | M3アダプター(出典引用) |
| `not_applicable` | 概念が適用されない | 代替費用法では生態系エンドポイント不適用 | M3アダプター |
| `not_covered` | 手法の評価範囲外 | LIME3表層水で土地利用評価が不提供 | M3アダプター(方法論に基づく) |
| `below_detection_or_rounding` | 閾値・丸めにより0 | 公表の丸め記載がある場合 | M3アダプター(出典の注記確認) |
| `missing` | 必要値が未取得 | データ不入手 | M3アダプター |
| `computed_zero` | 入力0等により計算結果が0 | 取水量0 × 係数 → 0 | M3アダプター |

**付与主体:** ゼロ意味は手法アダプター(M3)が、出典(資料・表・セル、またはAPI応答)を引用したうえで確定する。**M4は値の大きさや桁からゼロ意味を推論しない。** 同じ0に対して実装者ごとにラベルが変われば、§3.3が要求する負例の再現性が失われる。

**複数区分が当てはまる場合の優先順位:**

1. 出典が「該当なし」「評価対象外」等を明示していれば `not_applicable` / `not_covered` を採る
2. 出典が数値0を公表しているだけで、非該当・被覆外の明示がなければ `published_zero` を採る。`not_covered` へ格上げしない
3. 出典側の丸め・検出限界の記述が確認できる場合のみ `below_detection_or_rounding`
4. 自社の計算で入力0等から0になった場合のみ `computed_zero`
5. 取得できていない場合のみ `missing`

**例:** IFVIの日本 VFnutrition / VFdisease / VFaccess はAppendix D Table D1が0.00と公表した値であり、同時にIFVIモデルの計算結果でもある。規則2により `published_zero` を採り、`computed_zero` を候補として併記する。

## 5.9 (新) 完全分解・部分分解・停止

v_AとV_Bは同じ比較対象の正規化後の手法値とする。Fは、全部分集合について意味と計算式を定義できる要因集合である。

- **完全分解:** 必要な手法差をレシピがすべて表現し、`V* = V_A`も満たす。残差は数値許容誤差内でゼロになる。偶然値が一致しただけでは完全分解へ昇格しない
- **部分分解:** 数値化不能なモデル差等を固定して残す。`V* = V_A`を要求しない。固定した差異・除外要因・到達値V*・残差を表示する
- **停止:** 意味のある要因集合を定義できない、必要な部分集合を評価できない、または比較前提が成立しない場合。Fが空なら数値分解成功とせず、定性差異と停止理由を返す

中間の v(S) は、実際の式・集計・時間列を再実行して得る。根拠のある式が線形・乗法であること自体は禁止しない。固定倍率で異なるモデルの再実行を代用することを禁止する。

MAX、条件分岐、非線形較正等の相互作用を保持する。個別には交換可能でも組合せで意味を失う場合、その集合を実行しない。

## 6. エンドポイント被覆のデータ構造

### 6.1 用語の定義

**エンドポイント:** 因果連鎖のどこまで追って被害を数えるかの到達点。

```
取水 → 河川流量の減少 → 水生生態系の劣化 → 種の減少
                     ↘ 下流の農業用水不足 → 収量減 → 人間の栄養状態悪化
                     ↘ 自社の代替水源調達コスト
```

**被覆:** その手法が上記の連鎖のうち、どこを金額に含めているか。

| 手法 | 含むもの | 含まないもの |
|---|---|---|
| 代替費用法 | 自社の代替水源調達コスト | 生態系劣化、下流の健康影響 |
| LIME3 | 人間健康、生態系品質、一次生産、社会資産 | (交換価値としての自社コスト) |

**手法間の乖離の大半はここに由来する。** 精度の差ではなく、数えている範囲が違う。

### 6.2 2つのコード体系を併用する

構想書8.3の「サービス定義適合 = CICES/TEEB の階層一致度」は**適合度スコア(便益移転の誤差推定)用**であり、8.6/8.7 の「エンドポイント被覆メタデータ」とは**別軸**である。CICES には損害エンドポイントの分類が存在しない。

| 体系 | 何を分類するか | M4での用途 |
|---|---|---|
| **AoP(保護対象領域)** | 損害の到達先 | **影響側。**どこまで被害を数えたか |
| **CICES / TEEB** | 生態系サービスの種類 | **依存側。**どのサービスを対象にしているか |

**正規化 AoP コード(暫定):**

```
human_health          人間健康
ecosystem_quality     生態系品質
resource_availability 資源可用性
social_assets         社会資産
unmapped              対応付け不能(§0.2)
```

`unmapped` を用意することが要点。無理に4分類に押し込めない。

### 6.3 CICES の一致階層

**当初設定:Group 階層で一致とみなす。**

**2026-08-10訂正(公式スプレッドシートで確認済み):** CICES V5.1 の階層は **4層(Section > Division > Group > Class)** である。当初この節は「Section > Division > Group > Class > Class type」の5層としていたが、公式スプレッドシートの本文は "retains **four level** hierarchical structure" と明記しており、**Class type は階層ではなく、利用者がClassの下に任意に追加できる細分**である。実装(`SpecifiedLevel`)はもともと4値で正しかった。詳細と一次資料は `docs/data/cices-v51-notes.md`。

コードは階層が数字の前置部分に符号化されているため、最下層で保持しておけば上位階層での判定は文字列の切り出しで済む。**ただしコードを数値としてパースしてはならない**(未特定の階層に `X` が入る。例:`4.2.X.X`)。

```
"2.2.5.1" → Group 一致判定なら "2.2.5" で切る
          → Division 一致判定なら "2.2"
```

**変更可能性:** データを最も細かい階層で保持し、一致階層を実行時パラメータとする限り、**データ移行なしで後から変更できる。**

ただし次の2点で制約がある。

**制約1:出典側の粒度が粗い場合**

出典が「水質浄化」としか記載しておらず Class まで特定できない場合、下位への切り出しができない。したがって**どの階層まで特定できたかを併せて保持する。**

```typescript
{
  cicesCode: "2.2.5",       // 特定できたところまで
  specifiedLevel: "group",  // これがないと後から粒度を上げられない
  included: true
}
```

**制約2:過去の分析結果への遡及**

一致階層を変えると再グループ化の結果が変わり、「比較不能」だったペアが分解対象になる(またはその逆)。これは M8 の再計算ハッシュと期間比較の一貫性に直接影響する。

したがって一致階層は AssumptionEntry として記録し、**再計算ハッシュの入力に含める**。変更時は「手法変更時は前年度手法での再計算値を並記」という M4 の既定ルールと同じ扱い(変更理由の入力必須+旧設定での再計算値の並記)とする。

**つまり「後から変えられる」は正しいが、「表示設定のように自由に変えられる」ではなく「変更履歴を残せば変えられる」である。**

### 7.3.1 3要因すべてが一致し、乖離の100%が残差になる場合(2026-08-01追記)

M3のMVP水パイロットで実際に起こりうる具体例。IFVIのVFnutrition・VFdiseaseとLIME3の水消費値(いずれも`human_health`・厚生価値・割引なし)を比較する場合、3要因すべてに差がない可能性がある。

```
IFVIのVFnutrition vs LIME3(水・人間健康)

  エンドポイント被覆    ── 差なし(両方 human_health)──
  割引率                ── 差なし(両方 no_time_dimension)──
  地理較正              ── 差なし(両方、対象国自身の共変量を直接使用しており、
                                較正ブリッジが実質的に恒等変換)──
  ─────────────────────────────────────
  説明済み              ×1.00(寄与する要因なし)
  未説明乖離(残差)      ×N.NN   ← 乖離の100%が残差
```

読み下し文(自動生成)の例:

> IFVIとLIME3の値は、被覆するエンドポイント・割引率の扱い・地理較正のいずれも一致しています。**それでも生じているこの乖離は、本システムが分解対象とする3要因のいずれにも起因しません。** 手法固有の推定モデルやデータソースの違い(例:被害統計の推定方法、価値評価の技法そのものの違い)による可能性があります。

**これはバグではない。** M4の設計原則(§3.1・§7.3、残差を正式な分解項目として扱う)が意図通り機能した結果であり、「3要因では説明できない乖離が存在する」という事実そのものが監査・意思決定上の情報になる(§8.2参照)。

**将来の検討事項として記録するに留める:** 上記の例は、現行の3要因(エンドポイント被覆・割引率・地理較正)のいずれにも属さない**「価値評価の技法」**(例:VSLのような顕示選好ベースの推定 vs 意向調査のような表明選好ベースの推定)という第4の要因が、乖離の実体である可能性を示唆する。**ただしこれは今回追加する変更ではない。** D-12が手法数上限を可読性の制約としているのと同様、要因を増やすことは分解結果の可読性・監査説明のトレードオフを伴うため、独立した設計判断として別途扱う(§10 U-7として記録)。

### 7.4 代表値の選択

**システムが提供するのは判断材料であり、推奨ではない**(構想書9.3)。

同一グループ内で提示する事実:

- 各手法の適合度ティア分布
- 各手法が採用する価値概念
- 各手法が既にカバーするエンドポイント
- 前年度に選択した手法(事実の提示)
- 基準・ガイダンスが言及している手法か(事実の提示)

**手法変更時:** 変更理由の入力を必須化し、前年度手法での再計算値を並記する(手法変更の差分と実態変化の差分を分離するため)。

## 8. 監査・外部説明のための根拠

分解手法の正当性は「独自開発」ではなく、**既存の会計・経済学における標準手法の適用**として説明する。

| 先例 | 内容 | 本設計との対応 | 確度 |
|---|---|---|---|
| **原価差異分析(標準原価計算)** | 価格差異と数量差異の分解における結合差異の配分問題 | M4の順序依存問題と形式的に同一。会計監査人が既に理解している問題構造 | 高 |
| **構造分解分析(SDA)** | 産業連関分析での分解。Dietzenbacher & Los (1998) が順序依存性を扱い、Sun (1998) が全順序平均による完全分解を提示 | 本設計と同一手法 | 高 |
| **LMDI 分解** | IEA・IPCC 系のエネルギー・排出量要因分解の標準。対数空間・残差ゼロ | §4.1 の対数化を支持 | 高 |
| **成長会計 / ソロー残差** | 残差を正式な分解項目として扱う | §3.1・§7.3 の残差処理を支持 | 高 |
| **Oaxaca-Blinder 分解** | 賃金格差を説明可能部分と未説明部分に分ける労働経済学の標準 | 同上 | 高 |
| **Shapley 値による共通費配分** | 会計における結合原価配分への協力ゲーム理論の適用 | §4.2 | 中〜高 |

### 8.1 インパクト加重会計(IWA / IFVI)との関係

**IWA は M4 の先例ではなく、M4 の入力を供給する対象である。** IWA は「貨幣化して財務諸表に接続する」側の枠組みであり、手法間の乖離を分解する枠組みは持たない。

**監査説明の中核ロジック:**

> M4 は新たな評価を発明していない。各手法が自ら公表しているパラメータ(価値概念・エンドポイント被覆・割引率・地理較正)に沿って再パラメータ化しているだけである。

この主張が成立するのは、IWA/IFVI が方法論文書で当該パラメータを明示している限りにおいてである。**どこまで公開されているかは未確認(確度:中)。§0.3 の検証項目。**

## 付録:型定義(議論用ドラフト)

```typescript
type ValueConcept = "exchange" | "welfare";

type AoPCode =
  | "human_health"
  | "ecosystem_quality"
  | "resource_availability"
  | "social_assets"
  | "unmapped"        // 対応付けを試みたが判断できなかった(推定で埋めない)
  | "not_applicable"; // 2026-08-01追記:エンドポイントモデルを用いない手法(代替費用法等、M3 D-1のVFaccess)。
                      // "unmapped"(対応付け不能)とは区別する。§3.2の再グループ化ではnot_applicable同士を一致として扱う

type DecompositionFactor =
  | "endpointCoverage"
  | "discountRate"
  | "geographicCalibration";

interface EndpointCoverage {
  // 影響側:どこまで損害を数えたか
  areasOfProtection: {
    code: AoPCode;
    sourceLabel: string;        // 手法側の原表記(例 "一次生産")
    mappingConfidence: "high" | "medium" | "unmapped";
    included: boolean;
    metric?: "DALY" | "PDF" | "MSA" | null;
  }[];
  // 依存側:どの生態系サービスが対象か
  ecosystemServices: {
    cicesCode: string;                 // 例 "2.2.5.1"
    specifiedLevel: "section" | "division" | "group" | "class";
    included: boolean;
  }[];
}

interface MethodMetadata {
  methodId: string;
  version: string;
  valueConcept: ValueConcept;
  discountRate: number | null;
  discountRateStatus: "explicit" | "documented_zero" | "no_time_dimension";  // F-5
  geographicCalibration: {
    pppApplied: boolean;
    incomeElasticity: number | null;
    sourceRegion: string;
    targetRegion: string;
  };
  endpointCoverage: EndpointCoverage;
  recalculability: {                   // F-4 の判定材料
    endpointBreakdownPublished: boolean;
    damageTimeProfilePublished: boolean;
  };
}

type DecompositionMode =
  | "multiplicative"      // 通常
  | "additive"            // F-1
  | "not_decomposed";     // F-2 / F-3 / F-8 / 価値概念グループ間

interface FactorContribution {
  factor: DecompositionFactor;
  logContribution: number;        // c_i
  multiplier: number;             // exp(c_i)
  shareRatio: number | null;      // F-9 で null になりうる
  status: "decomposed" | "not_recalculable";
  exclusionReason?: string;
}

interface PairwiseDecomposition {
  methodIdA: string;
  methodIdB: string;
  valueA: number;
  valueB: number;
  ratio: number | null;           // not_decomposed のとき null
  mode: DecompositionMode;
  fallbackApplied: string[];      // 例 ["F-4", "F-9"]
  contributions: FactorContribution[];
  residual: {
    logResidual: number;
    multiplier: number;
  } | null;
  narrative: string;              // 自動生成の読み下し文
}

interface ValueConceptGroup {
  valueConcept: ValueConcept;
  methodIds: string[];
  usage: string;                  // "SSBJ財務影響 / 投資判断" 等
  pairwiseDecompositions: PairwiseDecomposition[];
}

interface DivergenceDecomposition {
  id: string;
  targetPhysicalQuantityId: string;
  siteId: string;
  valuationRecordIds: string[];   // 分割前の総数に上限なし。各ValueConceptGroup内で2 ≦ N ≦ 5(§2.1参照)
  groups: ValueConceptGroup[];
  crossGroupComparison: {
    incommensurable: true;        // 常に true。分解しない
    metadataDifferences: string[];
  } | null;
  representativeValueSelection?: {
    groupValueConcept: ValueConcept;
    selectedMethodId: string;
    reason: string;
    priorYearMethodId?: string;
    recalculatedWithPriorMethod?: number;
  };
  assumptionEntryIds: string[];
  recalculationHash: string;
}
```

### (改訂 2026-09-06) 型定義の変更

**`ValuationRecord.recalculability`** はトレース(`MethodEvaluationTrace.endpointBreakdown` / `damageTimeProfile`)から導出するミラーへ変更。フィールドは後方互換のため残すが、M4はトレースだけを読む。

**`PairwiseDecompositionV2`** は `DecomposedPair | StoppedPair` の型とする。停止理由コード一覧(`different_subject`, `sign_mismatch`, `counterfactual_sign_mismatch`, `value_concept_mismatch`, `recipe_not_found`, `recipe_version_mismatch`, `group_limit_exceeded` 等)を明示する。

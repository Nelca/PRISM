## 0. 最重要未検証事項 — 後続作業はここを参照すること

### 0.1 フェーズ0 C-3 の検証内容を再定義する

構想書10.2節では、フェーズ0の技術検証を「IFVI・CE Delft・LIME3のエンドポイント被覆/割引率/価値概念のメタデータが**機械可読または手作業で抽出可能か**」と定義している。

**この定義では不足している。** 本モジュールの設計を詰めた結果、実装に必要な条件は次の2段階であることが判明した。

| 段階 | 検証内容 | 現行C-3での扱い |
|---|---|---|
| **C-3a** | 各手法のメタデータ(価値概念/エンドポイント被覆/割引率/地理較正)が抽出可能か | 定義済み |
| **C-3b** | **抽出したメタデータを、手法横断の共通語彙に対応付けられるか** | **未定義。これが実装の真の前提** |
| **C-3c** | **各要因を差し替えた反実仮想の再計算が可能か**(§5.4参照) | **未定義。抽出できても再計算できなければ分解できない** |

**C-3aを通過してもC-3b・C-3cで詰まれば、M4は実装できない。** フェーズ0の検証設計を上記3段階に組み替えること。

### 0.2 C-3bが困難な理由 — AoP(保護対象領域)に共通体系が存在しない

依存側の生態系サービス分類には CICES という共通体系が存在するが、**影響側の損害到達先(AoP)には共通体系がなく、手法ごとに独自の分類を使っている。**

| 手法 | その手法が使うAoP呼称 | 正規化コードへの対応 | 確度 |
|---|---|---|---|
| LIME3 | 人間健康 / 社会資産 / 一次生産 / 生物多様性 | `human_health` / `social_assets` / **対応先不明** / `ecosystem_quality` | 中〜高 |
| ReCiPe 2016 | Human health / Ecosystems / Resource scarcity | `human_health` / `ecosystem_quality` / `resource_availability` | 中〜高 |
| IMPACT World+ | Human health / Ecosystem quality | `human_health` / `ecosystem_quality` | 中〜高 |
| CE Delft 環境価格 | 人間健康 / 生態系サービス / 建造物・材料 / 資源 / 厚生 | **4分類に収まらない** | 中 |
| IFVI | (方法論文書での確認が必要) | 未確認 | — |

**具体的な難所:**

- LIME3 の「一次生産」は、資源可用性とも生態系品質とも解釈でき、機械的な変換規則が存在しない
- CE Delft の「建造物・材料」は標準的な4分類のいずれにも素直に収まらない

この対応付けは**判断を伴う**。したがって:

1. 対応表そのものが AssumptionEntry の対象(誰がいつ、どの根拠で対応付けたか)
2. 対応表を後から変更すると、過去の分解結果が変わる(再計算ハッシュに影響)
3. 一部は「**対応付け不能**」として残す設計にする(§5.4の「推定で埋めない」原則の適用)

## 1. 位置づけ

M4は購入理由の中心であり、実装可否がフェーズ0の最優先検証事項(構想書9.2)。

**手法間の乖離倍率の表示だけでなく、乖離の「原因」の表示が必須要件である。** これがない場合、「3本並べただけ」に退化し、単一コンサル納品物に対する優位性が消える(構想書9.3)。

## 2. 入力

```
対象: 同一の物理量 × 同一地点 に対する ValuationRecord 群(N ≧ 2)
      各レコードは手法ID(版番号付き)と手法メタデータを持つ
```

### 2.1 比較手法数の上限

**上限 N = 5(ユーザーが選択)。**

制限の根拠は計算量ではなく、**出力の可読性と監査説明の単位**である。

- 計算量: N=5 で全ペア C(5,2)=10 ペア × 3要因の部分集合 2³=8 通り。中心値のみで60回程度の再計算であり、負荷にならない(N=10でも45ペア=270回)
- 可読性: 10ペアの分解結果を並べても、稟議でも監査でも読めない
- 実態: N=5でも §3 の価値概念分割により、各グループは2〜3手法に落ちるのが通常で、実質のペア数は3前後になる

**表示設計:** フットボールチャートを主表示とし、ペア分解はドリルダウンに置く。

## 3. 処理 — 2段構え(構想書8.2 の規律に従う)

構想書8.2は「交換価値と厚生価値は足せない。異なる概念の合算をシステムが物理的に禁止する」と定めている。

Shapley分解は定義上「手法Aの価値概念 × 手法Bのエンドポイント被覆」という混成体の値を計算することを要求するため、**価値概念を分解要因に含めると、8.2の規律を分解エンジン自身が破ることになる。**

したがって次の2段構えとする。

```
段階1: 価値概念で分割(partition)する。分解しない
       → 「これらは異なる問いに答えている」という事実の提示のみ
       → 価値概念をまたぐ差は「比較不能(incommensurable)」とラベルし、
          倍率を機械的に算出しない
       → 地理較正も含め、グループ間では一切分解しない(規律を単純に保つため)

段階2: 同一価値概念グループ内で、残り3要因のShapley分解を実行
       → エンドポイント被覆 / 割引率 / 地理較正
```

### 3.1 「価値概念の寄与」をどう扱うか

構想書0章は「何倍が問いの違いか」を謳っているが、これは**残差(residual)として提示する**。3要因で説明できた分を除いた未説明乖離として示し、価値概念が異なる場合はその残差が問いの違いに支配されている、という**記述**にとどめる。断定的に「価値概念の寄与 = ◯倍」とは出力しない。

これは構想書8.5の3層構造(層iii = スコープ・方法論不確実性は「数値に混ぜず、除外事項リストとして別枠で出力」)と整合する。残差を正式な分解項目として扱うことには成長会計(ソロー残差)・Oaxaca-Blinder分解という確立した先例がある(§8)。

### 3.2 再グループ化の判定基準

同一グループとみなす条件:

1. 価値概念が完全一致(必須)
2. エンドポイント被覆が一致(§6.3 の一致階層設定に従う)

## 4. 分解アルゴリズム — 対数空間 Shapley

### 4.1 なぜ対数空間か

構想書0章が求めているのは「その差のうち**何倍が**価値概念の違いで、何倍がエンドポイント被覆の違いか」という**乗法的分解**である。手法間の差が2桁で出る対象に加法分解を当てると、寄与額の大小が水準に引きずられて解釈不能になる。

```
ln V_A − ln V_B = c₁ + c₂ + c₃              (Shapley寄与、対数空間)
V_A / V_B       = exp(c₁) × exp(c₂) × exp(c₃)
```

残差なしの厳密な乗法分解が成立する。

### 4.2 Shapley寄与の算出

要因集合 F = { endpointCoverage, discountRate, geographicCalibration }(k=3)。

手法Bを基準、手法Aを対象とし、部分集合 S ⊆ F に対して「S に含まれる要因だけを B の設定から A の設定に差し替えて再計算した値」を v(S) と定義する。v(∅) = V_B、v(F) = V_A。

```
c_i = Σ_{S ⊆ F\{i}}  [ |S|! (k−|S|−1)! / k! ] × ( ln v(S ∪ {i}) − ln v(S) )
```

k=3 なら評価が必要な部分集合は 2³ = 8 通り(うち2つは既存の V_A・V_B なので新規計算は6回)。全6順列分の平均が上式で厳密に得られる。

### 4.3 満たす公理(監査時の検証対象)

| 公理 | 内容 | 監査上の意味 |
|---|---|---|
| 効率性 | Σc_i = ln V_A − ln V_B(残差ゼロ) | 説明されていない差が隠れていないことの保証 |
| 対称性 | どの要因も特権的な順序を持たない | 「なぜこの順で分解したか」の説明義務が消える |
| ゼロ寄与 | 差がない要因の寄与は必ず 0 | 無関係な要因に数字が付かない |
| 線形性 | 分解の加法性 | 複数対象の集計時の一貫性 |

**明示的に開示すべき規範的前提:** 全順列を等重みで平均するという仮定(対称性公理)は、「いずれの要因も他より根源的とはみなさない」という価値判断を含む。これは中立性の実装として説明可能であり、固定順序法が要求する「なぜこの要因を最初に置いたか」の説明よりも防御しやすい。この前提は AssumptionEntry として記録する(§9)。

## 5. フォールバック規則

対数分解は v(S) > 0 を全部分集合で要求する。以下の規則を実装必須とする。すべてのフォールバックは**出力に明示ラベルを付す**。

### F-0 事前条件チェック

全 2^k 個の v(S) を算出し、以下を判定してから分解モードを決定する。

```
1. 全て算出可能か         → 不可なら F-4
2. 符号が全て同一か        → 不一致なら F-2
3. 全て正か               → 非正を含むなら F-1
4. 極端な桁差がないか      → あれば F-3
5. 乖離が閾値以上か        → 未満なら F-8
```

### F-1 ゼロまたは負の値を含む

**条件:** いずれかの v(S) ≤ 0(かつ符号は全て同一 — 混在は F-2)

**処理:** 加法分解にフォールバックする。

```
V_A − V_B = c₁ + c₂ + c₃    (絶対額での分解)
```

**出力:** `decompositionMode: "additive"` を付与。**倍率表示を抑止し、絶対額のみを表示する。**

**理由:** 純便益を差し引く手法では負値が生じうる。倍率の解釈が成立しないため、乗法表示を出してはならない。

### F-2 手法AとBで符号が異なる

**条件:** V_A > 0 かつ V_B < 0、またはその逆

**処理:** **分解を実行しない。**

**出力:**
```
判定: 符号乖離(sign divergence)
「手法Aはこれを費用と評価し、手法Bは便益と評価しています。
  これは大小の差ではなく、費用か便益かという定性的な不一致です。
  倍率の算出および要因分解を行いません。」
```

**理由:** 符号の不一致は倍率の差より重大な発見であり、独立した論点として扱う。負の倍率に解釈可能な意味はない。

### F-3 極端な桁差(実質ゼロ)

**条件:** min(v) < 10⁻⁶ × max(v)(6桁超の差)

**処理:** 分解を実行しない。

**出力:**
```
判定: 被覆外(not covered)
「手法Bは当該影響を実質的に評価対象に含めていません(算出値がゼロ近傍)。
  これは評価額の差ではなく、被覆範囲の差です。
  倍率の算出を行いません。」
```

**理由:** 一方が実質ゼロを返すのは、当該エンドポイントを含んでいないためである。「10⁷倍の差」として提示するのは誤った表現であり、数値的にも対数寄与が不安定になる。

**注:** 閾値 10⁻⁶ は暫定値。フェーズ0の実データで見直す(§10)。

### F-4 再計算不能な要因がある

**条件:** ある要因 i について、差し替え後の値が算出できない
(例:損害の時間プロファイルが非公開 → 割引率のみの差し替えが不能)

**処理:** 当該要因を要因集合から除外し、k を減らして分解する。除外した要因が担っていた差は**残差**に落ちる。

```
説明済み   ×2.31
未説明乖離  ×1.16   ← 分解できなかった差
```

**出力:** 除外した要因と、除外理由(どのデータが欠けているか)を明示する。

**設計原則 — 推定で埋めない:**

> 再計算できない要因は推定せず「分解不能」と出力する。構想書9.4の除外事項(X1〜X6)と同じ思想であり、「貨幣化しない判断を仕様として明示することが逆に信頼の証明になる」という立場を分解ロジックにも適用する。**推定値が1つ混じった時点で、分解全体の監査価値が失われる。**

要因ごとの再計算可能性の見通し:

| 要因 | 再計算可能性 | 根拠 |
|---|---|---|
| 地理較正 | **高。自前で完全に再計算可能** | 構想書8.4に補正式(PPP × 所得弾力性^η × デフレータ × 相対価格 × 面積スケーリング)があり、外部依存がない |
| 割引率 | 中。損害の時間プロファイルが公開されていれば可 | 時間分布が非公開だと差し替え不能 |
| エンドポイント被覆 | 中〜低。エンドポイント別内訳の公開が必須 | 総額のみの公開だと分解不能 |
| 価値概念 | 原理的に不能 | §3 のとおり分解対象から除外 |

### F-5 割引率が null の扱い

3通りに区別する。**この区別を実装しないと、構造的な差異と表記上の差異が混同される。**

| ケース | 条件 | 処理 |
|---|---|---|
| **F-5a** | A・B ともに割引率を持たない | 要因を落として k=2 で分解。残差は生じない(ゼロ寄与公理により正当) |
| **F-5b** | 一方が「割引しない(=0%)」と文書上明示 | 0% として扱い、通常どおり再計算する |
| **F-5c** | 一方が時間次元を持たない(年間フロー評価等) | 割引率の差し替えが定義できない → **F-4 として扱い、残差に落とす** |

### F-6 レンジ(モンテカルロ結果)の扱い

**MVP では中心値のみを分解対象とする。** レンジは M3 の出力として別途併記する。

要因別に分位点を分解する設計は本質的に別問題であり、MVP スコープ外(§10)。

### F-7 効率性公理の数値検証

```
assert( |Σc_i − (ln V_A − ln V_B)| < 1e-9 )
```

対数空間 Shapley は構成上厳密に一致するため、逸脱は実装バグを意味する。**逸脱時は結果を出力せずエラーとする**(誤った分解を出すより出さない)。

### F-8 乖離が軽微な場合

**条件:** |ln(V_A / V_B)| < ln(1.05)(差が 5% 未満)

**処理:** 分解を実行しない。

**出力:** 「有意な乖離なし」と表示。

**理由:** 分母が小さいと寄与割合が発散し、意味のない大きな百分率が表示される。

### F-9 寄与の符号が相殺する場合(表示規則)

個々の c_i は、合計が正でも負になりうる(相殺し合う要因)。

**絶対値を取ってはならない。** 相殺の事実自体が発見である。

**表示規則:** いずれかの c_i が合計と逆符号の場合、**寄与割合(%)の表示を抑止し、倍率(exp(c_i))のみを表示する。** 割合が100%超や負値になり誤読を招くため。

## 6. エンドポイント被覆のデータ構造

### 6.1 用語の定義

**エンドポイント:** 因果連鎖のどこまで追って被害を数えるかの到達点。

```
取水 → 河川流量の減少 → 水生生態系の劣化 → 種の減少
                     ↘ 下流の農業用水不足 → 収量減 → 人間の栄養状態悪化
                     ↘ 自社の代替水源調達コスト
```

**被覆:** その手法が上記の連鎖のうち、どこを金額に含めているか。

| 手法 | 含むもの | 含まないもの |
|---|---|---|
| 代替費用法 | 自社の代替水源調達コスト | 生態系劣化、下流の健康影響 |
| LIME3 | 人間健康、生態系品質、一次生産、社会資産 | (交換価値としての自社コスト) |

**手法間の乖離の大半はここに由来する。** 精度の差ではなく、数えている範囲が違う。

### 6.2 2つのコード体系を併用する

構想書8.3の「サービス定義適合 = CICES/TEEB の階層一致度」は**適合度スコア(便益移転の誤差推定)用**であり、8.6/8.7 の「エンドポイント被覆メタデータ」とは**別軸**である。CICES には損害エンドポイントの分類が存在しない。

| 体系 | 何を分類するか | M4での用途 |
|---|---|---|
| **AoP(保護対象領域)** | 損害の到達先 | **影響側。**どこまで被害を数えたか |
| **CICES / TEEB** | 生態系サービスの種類 | **依存側。**どのサービスを対象にしているか |

**正規化 AoP コード(暫定):**

```
human_health          人間健康
ecosystem_quality     生態系品質
resource_availability 資源可用性
social_assets         社会資産
unmapped              対応付け不能(§0.2)
```

`unmapped` を用意することが要点。無理に4分類に押し込めない。

### 6.3 CICES の一致階層

**当初設定:Group 階層で一致とみなす。**

CICES V5.1 は Section > Division > Group > Class > Class type の階層構造を持つ(確度:高。フェーズ0で公式スプレッドシートにより要確認)。コードは階層が数字の前置部分に符号化されているため、最下層で保持しておけば上位階層での判定は文字列の切り出しで済む。

```
"2.2.5.1" → Group 一致判定なら "2.2.5" で切る
          → Division 一致判定なら "2.2"
```

**変更可能性:** データを最も細かい階層で保持し、一致階層を実行時パラメータとする限り、**データ移行なしで後から変更できる。**

ただし次の2点で制約がある。

**制約1:出典側の粒度が粗い場合**

出典が「水質浄化」としか記載しておらず Class まで特定できない場合、下位への切り出しができない。したがって**どの階層まで特定できたかを併せて保持する。**

```typescript
{
  cicesCode: "2.2.5",       // 特定できたところまで
  specifiedLevel: "group",  // これがないと後から粒度を上げられない
  included: true
}
```

**制約2:過去の分析結果への遡及**

一致階層を変えると再グループ化の結果が変わり、「比較不能」だったペアが分解対象になる(またはその逆)。これは M8 の再計算ハッシュと期間比較の一貫性に直接影響する。

したがって一致階層は AssumptionEntry として記録し、**再計算ハッシュの入力に含める**。変更時は「手法変更時は前年度手法での再計算値を並記」という M4 の既定ルールと同じ扱い(変更理由の入力必須+旧設定での再計算値の並記)とする。

**つまり「後から変えられる」は正しいが、「表示設定のように自由に変えられる」ではなく「変更履歴を残せば変えられる」である。**

## 7. 出力

### 7.1 段階1:価値概念による分割

```
┌─ 交換価値グループ ────────────────────┐
│  A. 代替費用法          2,500万円      │
│  用途: SSBJ財務影響 / 投資判断          │
└──────────────────────────────────────┘
        ╎
        ╎  32倍の差  ⚠ 比較不能(incommensurable)
        ╎  この差は精度の差ではありません。
        ╎  2つは異なる問いに答えています。
        ╎  → 分解を行いません(理由を見る)
        ╎
┌─ 厚生価値グループ ────────────────────┐
│  B. IFVI Water          8億円          │
│  C. LIME3               3億円          │
│  用途: 社会的費用ビュー / 開示          │
└──────────────────────────────────────┘
```

「理由を見る」の内容:

> 交換価値は市場でやり取りされる価格に相当し、厚生価値は社会が被る損失(支払意思額基準)です。この2つを割り算した倍率には解釈可能な意味がありません。本システムは、異なる価値概念間の要因分解および合算を構造的に禁止しています(設計規律 8.2)。
>
> **メタデータ上の差異(参考・数値化しない):**
> - 価値概念: 異なる ← この差が支配的
> - エンドポイント被覆: 異なる(Aは自社代替コストのみ、B/Cは人間健康・生態系品質を含む)
> - 割引率: A=なし / B=2.0% / C=3.0%
> - 地理較正: A=不要 / B・C=適用済

### 7.2 段階2:グループ内の Shapley 分解

```
B / C = 2.67倍   [ln 2.67 = 0.982]

  エンドポイント被覆    ×2.10   (寄与 75%)  ████████████████░░░░
  割引率                ×1.15   (寄与 14%)  ███░░░░░░░░░░░░░░░░░
  地理較正              ×1.10   (寄与 11%)  ██░░░░░░░░░░░░░░░░░░
  ─────────────────────────────────────
  積                    ×2.67   (残差 0)  ← 効率性公理により厳密に一致
```

読み下し文(自動生成):

> IFVI Water と LIME3 の 2.67倍の差のうち、**2.10倍分は数えている損害の範囲の違い**です。IFVI は生態系品質への損害(PDF)を含みますが、LIME3 の当該係数はこれを含みません。残りは割引率(2.0% vs 3.0%)と地理較正の差によるものです。
>
> **この差は精度のばらつきではなく、方法論上の範囲の違いです。**

### 7.3 残差が生じる場合(F-4)

```
B / C = 2.67倍

  エンドポイント被覆    ×2.10   (寄与 75%)
  地理較正              ×1.10   (寄与 11%)
  割引率                ── 分解不能 ──
     理由: LIME3の損害の時間プロファイルが非公開のため、
           割引率のみを差し替えた再計算ができません
  ─────────────────────────────────────
  説明済み              ×2.31
  未説明乖離(残差)      ×1.16   ← 分解できなかった差
```

### 7.4 代表値の選択

**システムが提供するのは判断材料であり、推奨ではない**(構想書9.3)。

同一グループ内で提示する事実:

- 各手法の適合度ティア分布
- 各手法が採用する価値概念
- 各手法が既にカバーするエンドポイント
- 前年度に選択した手法(事実の提示)
- 基準・ガイダンスが言及している手法か(事実の提示)

**手法変更時:** 変更理由の入力を必須化し、前年度手法での再計算値を並記する(手法変更の差分と実態変化の差分を分離するため)。

## 8. 監査・外部説明のための根拠

分解手法の正当性は「独自開発」ではなく、**既存の会計・経済学における標準手法の適用**として説明する。

| 先例 | 内容 | 本設計との対応 | 確度 |
|---|---|---|---|
| **原価差異分析(標準原価計算)** | 価格差異と数量差異の分解における結合差異の配分問題 | M4の順序依存問題と形式的に同一。会計監査人が既に理解している問題構造 | 高 |
| **構造分解分析(SDA)** | 産業連関分析での分解。Dietzenbacher & Los (1998) が順序依存性を扱い、Sun (1998) が全順序平均による完全分解を提示 | 本設計と同一手法 | 高 |
| **LMDI 分解** | IEA・IPCC 系のエネルギー・排出量要因分解の標準。対数空間・残差ゼロ | §4.1 の対数化を支持 | 高 |
| **成長会計 / ソロー残差** | 残差を正式な分解項目として扱う | §3.1・§7.3 の残差処理を支持 | 高 |
| **Oaxaca-Blinder 分解** | 賃金格差を説明可能部分と未説明部分に分ける労働経済学の標準 | 同上 | 高 |
| **Shapley 値による共通費配分** | 会計における結合原価配分への協力ゲーム理論の適用 | §4.2 | 中〜高 |

### 8.1 インパクト加重会計(IWA / IFVI)との関係

**IWA は M4 の先例ではなく、M4 の入力を供給する対象である。** IWA は「貨幣化して財務諸表に接続する」側の枠組みであり、手法間の乖離を分解する枠組みは持たない。

**監査説明の中核ロジック:**

> M4 は新たな評価を発明していない。各手法が自ら公表しているパラメータ(価値概念・エンドポイント被覆・割引率・地理較正)に沿って再パラメータ化しているだけである。

この主張が成立するのは、IWA/IFVI が方法論文書で当該パラメータを明示している限りにおいてである。**どこまで公開されているかは未確認(確度:中)。§0.3 の検証項目。**

## 0. 位置づけ

購入理由の一部(構想書9.2)。係数自体は既存資産(IFVI等)を使い、**自前構築するのは複数手法の切替・横断比較の基盤**(design-rationale-log D-03)。

**M4との接続で必須:** ValuationRecordにMethodMetadata(価値概念/エンドポイント被覆/割引率/地理較正/再計算可能性フラグ)を必ず持たせる。ここが欠けるとM4が動かない(build-plan §5.2)。

**MVP範囲:** 1カテゴリ(水)× 2〜3手法(IFVI / 代替費用法 / LIME3)、モンテカルロによるレンジ算出、トルネード図、適合度ティア(A/B/C)、地理較正、ValuationRecordの生成。

## 1. 決定事項 D-1:IFVIの水消費値は集計値のまま扱わず、内訳4本に分解して取り込む

### 対象の構造

IFVI Water Consumption Topic Methodology(最終版)は次の集計式を持つ(`docs/data/aop-mapping-v1.md` §1.3)。

```
VFH2O = VFaccess + MAX(VFnutrition, VFdisease, VFes)
```

- VFnutrition・VFdisease・VFes:WTPベース(厚生価値寄り)
- VFaccess:代替費用モデル(交換価値寄り)

**IFVIの公式集計値1本には、構想書8.2が禁止する「異なる価値概念の合算」に相当する構造が既に内在している。**

### 検討した案

| 案 | 内容 | 判定 |
|---|---|---|
| A案 | IFVIの公式集計値をそのまま1本のValuationRecordとして取り込む | 却下 |
| **B案** | **4本の内訳値(VFnutrition/VFdisease/VFes/VFaccess)を、それぞれ独立したValuationRecordとして生成する** | **採用** |

### 却下理由(A案)

- 価値概念タグを単一に決められない。「厚生価値」も「交換価値」も、いずれも不正確なラベル付けになる
- 構想書8.2/design-rationale-log D-11の最重要規律(価値概念の混在を型で禁止する)を、入力データの時点で骨抜きにすることになり、監査文脈で「なぜIFVIの入力だけ例外か」を説明できなくなる

### 採用理由(B案)

1. 8.2の規律を保てる。M4の段階1(価値概念での分割)にそのまま乗る
2. **副次的な利点:** LIME3の水消費損害は100%人間健康エンドポイントに配分される(`method-recalculability.md` §3.3)。B案を採用すると、IFVIのVFnutrition/VFdiseaseとLIME3の人間健康値を**同一AoP同士で直接比較**できる。これは集計値のまま比較するより、乖離分解(M4)の説明力を上げる

### 生成されるValuationRecordの構成(水カテゴリ・IFVI)

| ValuationRecord | 価値概念 | AoP(正規化コード) | 割引率の扱い |
|---|---|---|---|
| VFnutrition | welfare(厚生価値) | `human_health` | 割引なし(F-5c相当・時間次元なし) |
| VFdisease | welfare(厚生価値) | `human_health` | 割引なし(F-5c相当) |
| VFes | welfare(厚生価値) | `resource_availability` | 未確認(`method-recalculability.md` §2.3の未決事項) |
| VFaccess | exchange(交換価値) | AoP対象外(代替費用モデル) | 2%・2080年まで(F-5b相当・明示的割引率) |

## 2. 決定事項 D-2:集計整合性検証(Reconciliation Check)を必須実装とする

### 背景

D-1(分解して取り込む)を採用したことで生じる新たなリスク:「IFVIの回答」(公式集計値)と「PRISMが4本の内訳から再集計した値」が食い違う可能性。**この食い違いは製品の根幹の説明可能性を破壊するため、絶対に避けなければならない。**

このリスクの性質は、外部データが汚れているケース(推定で埋めない、という既存原則の対象)ではなく、**PRISM側の実装バグ**(MAXの選択ロジックの誤り、単位の取り違え等)によって起きる。したがって「データ品質チェック」ではなく「実装の正しさを常に検証する不変条件」として設計する。

### 実装要件

1. **集計関数を独立した純粋関数として実装する。** `reconstructVF(nutrition, disease, es, access) = access + max(nutrition, disease, es)` をIFVIのEq.2をそのまま写した単独関数とし、4本の内訳値の計算ロジックと混在させない
2. **ゴールデンテストを正常系より先に書く**(build-plan §9.1、M4のF-7と同じ規律)。IFVIのBasis for Conclusions文書に計算例が含まれるか確認し、含まれていればそれをテストケース化する。含まれていなければ、既知の入力(水ストレス比・GNI PPP等)から4本の内訳値を手計算し、テストベクタとして固定する
3. **本番実行時も復元集計値を必ず算出し、ValuationRecord群に併記する。** UIは常に「この4本を公式集計式に通すとこの値になる」という復元値を表示し、IFVI公式値と一致していることを利用者が確認できる状態にする
4. **逸脱時はエラーとする(M4のF-7と同一方針)。** 復元集計値と期待値の差が許容誤差を超えた場合、分解結果を提示せずエラーとする。「誤った分解を出すより出さない」
5. **AssumptionEntryへの記録:** 集計関数の版番号とゴールデンテストの検証結果を再計算ハッシュの入力に含める(design-rationale-log D-04「M8は構造を初日から完全に」の思想と接続。具体的な記録先はM8要件定義書で確定)

### 一般化される設計原則

**これはIFVI固有の対応ではない。** 「複数の内訳値を非単純な関数(MAX、条件分岐等)で集計する外部手法」全般に適用する設計パターンとして記録する。将来CE Delft等の他手法で同様の複合構造が見つかった場合、同じ機構を再利用する。

## 3. 決定事項 D-3:プラグインインターフェース、および地理較正の一律適用

### 3.1 プラグインの契約

D-1(1手法=N本のレコードを返しうる)を前提に、以下のインターフェースとする。

```typescript
// 手法プラグインの契約
interface MonetizationMethodPlugin {
  methodId: string;
  version: string;                    // 係数セット・方法論文書のバージョン
  licenseMode: "embedded" | "reference_only" | "bring_your_own_license";
  supportedCategories: ImpactCategory[];

  // 中心値・分位点レンジを計算する。較正前の値を返すこと(地理較正はコアエンジン側で一律適用)
  evaluate(input: PhysicalQuantityInput, config: MethodConfig): MethodOutput[];

  // 複合手法(MAX+加算等、非単純な集計関数を持つ手法)のみ実装する
  reconciliation?: ReconciliationSpec;
}

interface PhysicalQuantityInput {
  category: ImpactCategory;
  physicalQuantity: number;
  unit: string;
  siteId: string;
  sourceRegion: string;    // 係数の出典地域。地理較正ブリッジの入力
  targetRegion: string;    // 評価対象地域(通常は日本)
}

interface MethodOutput {
  subFactorId: string;                  // 例 "VFnutrition"。単純な手法では手法IDと同一でよい
  valueConcept: "exchange" | "welfare";
  aopCode: AoPCode;   // "not_applicable"はAoPCode自体に含まれる(M4 2026-08-01追記で統合済み)。代替費用モデル等はこの値を使う
  cicesRef?: { cicesCode: string; specifiedLevel: "section" | "division" | "group" | "class" };  // M4付録の型定義と統一(フィールド名・値を揃える)
  centralValue: number;                  // 較正前(source region)の値
  quantileRange: QuantileRange;          // 層i:パラメータ不確実性
  discountRate: number | null;
  discountRateStatus: "explicit" | "documented_zero" | "no_time_dimension";  // F-5
  scopeExclusions: string[];             // 層iii:除外事項(数値に混ぜない)
}

interface ReconciliationSpec {
  reconstruct(outputs: MethodOutput[]): number;    // IFVIならEq.2そのもの
  goldenTestVectors: {
    input: PhysicalQuantityInput;
    expectedAggregate: number;
    source: string;                     // 例 "IFVI Basis for Conclusions, worked example 1"
  }[];
  tolerance: number;
}
```

### 3.2 地理較正は常にコアエンジンが一律適用する(プラグインには実装させない)

**決定:** プラグインは常に「較正前」の値(`MethodOutput.centralValue`、出典地域=`sourceRegion`のままの値)を返す。地理較正(構想書8.4式:PPP × 所得弾力性^η × デフレータ × 相対価格上昇係数 × 面積スケーリング)は、手法によらずコアエンジンが一律に適用する共通関数として実装する。

**却下した案:** 手法が既に較正済みの値(例:IFVIの「Global」視点、PPP調整済み)を提供している場合、それをそのまま使いコアエンジンの較正をスキップする。

**却下理由:**
1. 二重適用のリスク(IFVIの「Global」値は既にPPP調整済みのため、その上にコアエンジンの較正を重ねると誤った値になる)
2. 手法ごとに較正ロジックが異なると、M4の乖離分解における地理較正要因が「同一ロジックの差し替え」という前提を満たせなくなり、要因として独立に取り出せなくなる
3. 外部方法論が較正ロジックを改訂した場合、PRISM側が個別に追従する必要が生じ、再計算ハッシュの設計が複雑化する

**監査対応として要件化する事項(採用の前提条件):**
1. 使用するPPPデータの出典・年次を明記する(世界銀行ICP等の公的データを使用し、恣意的な数値を使わない)
2. 所得弾力性(η)の採用値と根拠文献を明記する
3. 地理較正のパラメータ(出典地域・対象地域・PPP値・η・デフレータ・面積スケーリング)を常にドリルダウンで確認できるUIとする(M5の非GAAPラベルと同じ思想の常時開示)
4. AssumptionEntry・再計算ハッシュに較正パラメータの版を含める(既存のM8設計と接続)

**監査上の位置づけ:** これは「PRISM独自の計算だから弱い」のではなく、**PPP×所得弾力性による便益移転はベネフィット・トランスファー分野の標準手法であり、IFVI自身もGlobal視点で同種の調整を行っている。** M4の監査対応(§8「既存の会計・経済学における標準手法の適用として説明する」)と同型のロジックで説明する。

### 3.3 地理較正の具体例(2026-08-02追記)

IFVIのVFes(生態系サービス毀損)が、研究の基準地域(欧州、仮に所得水準を100とする)の値として`centralValue: 500円/m³`を返したとする。これを対象地域(日本、所得水準を仮に130とする)に較正する。

```
PPP係数        = 1.15(世界銀行ICP、2024年時点の対円レート換算)
所得弾力性調整  = (130 / 100) ^ 0.7  ≈ 1.20   ※ η=0.7は環境財WTPの所得弾力性の一般的な採用値
デフレータ      = 1.03(研究時点から評価年までの物価調整)
面積スケーリング = 1.0(対象地の面積が研究地とほぼ同規模のため調整なし)

較正後の値 = 500円 × 1.15 × 1.20 × 1.03 × 1.0 ≈ 712円/m³
```

この712円/m³が、M4の乖離分解に渡される`centralValue`(較正後)になる。**PPP係数・所得弾力性(η=0.7)・デフレータの各値は、AssumptionEntryに記録され、後から検証・変更できる**(§3.2の監査対応要件)。

## 4. 決定事項 D-4:3層不確実性の扱い

構想書8.5の3層を`MethodOutput`に落とし込む。

### 4.1 層i(パラメータ不確実性)と層ii(移転誤差)は対数空間で乗法的に合成する

理由:M4が既に「乖離は倍率(乗法)で捉える」という設計哲学(§4.1 対数空間Shapley)を採用しているため、不確実性の合成もこれに揃える。実装上は、モンテカルロの各試行で層iの分布と層iiの分布から独立にサンプルを引き、掛け合わせる(対数空間では加算に相当)。独立な誤差の合成であるため、両誤差の単純な合算(例:20%+40%=60%)より穏やかな幅になる(二乗和平方根に近い挙動)。

**広い幅が出ること自体は欠陥ではない。** ティアCのように移転の当てはまりが悪いデータは正直に幅を広く出すべきで、その広い幅のおかげで「この論点はどう転んでも承認閾値をまたがない」と分かれば、安く・速く「効かない」と確定できる(M6 ★判定)。ティアA〜Cごとの具体的な誤差幅の数値(恣意的に決めない)は、論点5(適合度ティアの閾値)で、便益移転誤差に関する既存研究を参照して決定する。

### 4.2 層iiが構造的に適用できない`MethodOutput`がある — `not_applicable`を追加する

構想書8.3の適合度スコア(5次元)は「研究地点の値を対象地点に移転する」便益移転を前提にした概念である。しかし今回確定したIFVIの4本の内訳値のうち、便益移転をしているのはVFes(ESVDからのベネフィット・トランスファー)のみで、VFnutrition・VFdisease(対象国自身の共変量を使った直接パラメトリック計算)、VFaccess、代替費用法、およびLIME3の水(国別直接データの可能性が高い、要確認)には、そもそも「移転」という行為が発生していない。

**「移転していない」ケースを無理にティアA(移転はしたが精度が高い)に押し込めない。** 理由が違うものを同じラベルにすると、監査時に「なぜこの評価はAなのか」を正しく説明できなくなる(既存の`unmapped`・`not_applicable`と同じ設計原則、design-rationale-log D-15参照)。

**採用:** `tier: "A" | "B" | "C" | "not_applicable"` の4値とする。

**MVPでの適用状況の見立て(要確認・確定ではない):**

| MethodOutput | 層iiの適用 |
|---|---|
| VFes(IFVI) | 適用(ESVDベネフィット・トランスファー) |
| VFnutrition・VFdisease(IFVI) | 対象外(直接パラメトリック計算) |
| VFaccess(IFVI) | 対象外(代替費用モデル) |
| LIME3(水) | 対象外の可能性が高い(G20各国への直接調査データの可能性。要確認) |
| 代替費用法 | 対象外(自地点の直接算定) |

**この状態は問題ではない。** MVP(水カテゴリ)でティア判定が適用されるのが実質1本であっても、適合度ティアの仕組み自体は水以外のカテゴリ(土地利用・淡水・海洋利用改変・生物資源等、構想書7.2のティアII)で本領を発揮する設計であり、水カテゴリで使用頻度が低いことは仕組みの不要性を意味しない。build-plan §4.1が適合度ティアを「薄くしてはいけない項目」としているのはこのため。

### 4.3 層iii(スコープ・方法論不確実性)はMVPでは単純な文字列配列とする

数値分布に混ぜず、除外事項リストとして別枠で保持する。構造化(カテゴリ分け等)はMVPでは行わず、後回しでよい。ただし「何を除外したか」を`null`や空配列で済ませず、判断が発生した箇所で必ず記述することを要件とする(D-15と同じ原則)。

### 4.4 レンジ(quantileRange)のD-2整合性検証はMVPスコープ外

M4のF-6(「MVPでは中心値のみを分解対象とする」)に合わせ、D-2の集計整合性検証(reconciliation check)は`centralValue`(点推定値)のみを対象とする。IFVIのMAX集計を分布(レンジ)のレベルで正しく合成する検証(MAXを取る複数分布の合成は単純な分位点の四則演算では再現できない)は、MVPスコープ外とし、未決定事項として残す。

### 型への反映

```typescript
interface MethodOutput {
  // ...既存フィールド(§3.1参照)
  parameterUncertainty: Distribution;        // 層i

  transferFitness: {
    tier: "A" | "B" | "C" | "not_applicable";
    dimensions?: {                            // tierがA/B/Cの場合のみ

      spatialScaleFit: number;
    };
  };                                          // 層ii

  quantileRange: QuantileRange;               // 層i×層ii合成後の最終分位点
  scopeExclusions: string[];                  // 層iii
}
```

## 5. 決定事項 D-5:適合度ティア(A/B/C)の閾値

### 5.1 前提:文献に3段階分類は存在しない

便益移転誤差の文献調査の結果、**「A/B/Cのような3段階の信頼度分類」自体は既存研究に存在しないことを確認した。** ESVD自身も定量的な精度目安を出しておらず、「専門知識が必要、文脈込みで解釈すること」という定性的な注意喚起があるのみ(esvd.info/value-transfer)。文献にあるのは、類似度に応じた連続的な誤差の実測値のみである。

> 出典: Rosenberger (2015) *J. Environmental Economics and Management*(収束的妥当性メタ分析)、Johnston & Rosenberger (2010) *Journal of Economic Surveys*、Ready & Navrud, *Environmental and Resource Economics*(欧州5カ国の国際移転検証)、Brander et al. (2006) 湿地の包括的メタ分析

**したがって「3段階のティア」自体はPRISM独自の設計判断である。** ただし各ティアに割り当てる誤差幅の大きさは、以下の実測値を錨(アンカー)として設定し、恣意的な数値にしない。

| 出典 | 誤差の実測値 |
|---|---|
| Rosenberger (2015)、収束的妥当性メタ分析 | function transferで中央値36%、value transferで中央値45% |
| Johnston & Rosenberger (2010) | 中央値39% |
| Ready & Navrud(欧州5カ国の国際移転検証) | 平均38%(所得・人口構成の補正を加えても改善せず) |
| Brander et al. (2006)、湿地の包括的メタ分析 | 平均74%(10%以下の精度は全体の5分の1未満) |
| 精緻化されたメタ回帰移転関数(湿地、引用確度は中) | 中央値17%程度 |

### 5.2 採用する閾値とティア別誤差幅

```
適合度 = 加重幾何平均(5次元スコア、均等加重。根拠:design-rationale-log D-10の対称性公理と同じ理屈 — 
         特定次元を特権化する根拠を持たないため均等加重とする)

A: 適合度 ≥ 0.8   → 層iiの誤差幅 目安 ±20%(精緻化されたfunction transferの良好事例17%に近い水準)
B: 0.5〜0.8       → 層iiの誤差幅 目安 ±40%(Rosenberger 36%・Johnston&Rosenberger 39%・Ready&Navrud 38%の中央値群と整合)
C: < 0.5          → 層iiの誤差幅 目安 ±75%、上限は打たない(Brander et al. 74%、および文献全体の
                    「100%を超えることもある」という知見を反映。モンテカルロの分布形状(対数正規等)で裾を自然に表現する)
```

**具体例(2026-08-02追記):** VFes(生態系サービス毀損、ESVDからのベネフィット・トランスファー)の5次元スコアが以下だったとする。

```
生態的適合           0.9   (研究地・対象地とも同じ湿地バイオーム)
社会経済的適合       0.6   (所得水準にやや差がある)
サービス定義適合     0.8   (CICES Group階層まで一致)
時間的距離           0.7   (研究は8年前のもの)
空間スケール適合     0.75  (面積比が近い)

適合度 = (0.9 × 0.6 × 0.8 × 0.7 × 0.75) ^ (1/5) ≈ 0.75
```

0.75は「0.5〜0.8」の範囲に入るため、**ティアB(層iiの誤差幅 目安±40%)と判定される。** この0.75というスコアと、判定根拠になった5次元の内訳は、AssumptionEntryに記録される(M8 D-1)。

### 5.3 監査対応上の注記(重要)

**この設計は、design-rationale-log D-10(独自手法ではなく標準手法の適用として説明する)とは性質が異なる。** 境界線(0.8/0.5という区切り、A/B/Cという3段階そのもの)はPRISM独自の設計判断であり、既存文献にそのまま存在するものではない。**ただし各段階に割り当てる誤差幅の大きさは、実証研究の実測値を錨として設定しており、恣意的ではない。** 監査・開示の文脈では、この2つを区別して説明すること:「ティアの区切り方はPRISM独自の設計」「各ティアの誤差幅は公表された実証研究の値に基づく」。

### 5.4 暫定値としての位置づけ

0.8/0.5というスコア閾値、および±20%/±40%/±75%という誤差幅は、**M4のF-3(桁差閾値10⁻⁶)・F-8(有意乖離閾値5%)と同じ扱いの暫定値**であり、フェーズ0で実際のESVD日本カバレッジのデータを用いて見直す。

## 6. 決定事項 D-6:ESVD要約値の使用範囲

### 6.1 根拠

ESVD自身のドキュメント(esvd.info/value-transfer)が、**「要約統計(high-level summary statistics)は価値移転に使うべきではない」と明記している**(多様な研究地点の文脈を1つの平均値に混在させてしまうため)。これはbuild-plan §5.2が既定していた区分(スクリーニング=ティアCのみ、深掘りは個別レコード照合)と正確に一致する。推測ではなく提供元自身の使用上の注意書きに基づく。

### 6.2 採用する設計

```
評価深度(M2の「深度可変」設計と対応)によってESVDデータへのアクセス粒度を切り替える:

スクリーニング:
  - ESVDの要約統計(バイオーム別平均値等)を使用可
  - 5次元適合度スコアは計算せず、無条件にティアC固定とする

深掘り:
  - 個別のESVDレコード(特定研究・特定バイオーム・特定地域)を選択する
  - 実際に5次元スコアを計算し、A/B/Cを判定する(ここでは真にA評価も起こりうる)
```

**「ティアC固定」であって「5次元スコアで判定した結果としてのC」ではない点が要点。** ESVDの要約統計は特定の研究地点を指さないため、「生態的適合」「時間的距離」等を採点する対象がそもそも存在しない。D-4で導入した`not_applicable`(移転という行為自体が発生していないケース)とも異なり、こちらは「要約統計という性質上、個別地点との適合を測ること自体が無意味」なケースであるため、スコア計算を試みず直接ティアCを割り当てる。

### 6.3 ライセンスとの関係(未確認・`licensing.md`待ち)

ESVDの要約統計と個別レコードで、商用利用・再配布の条件が異なる可能性がある。`licensing.md`確定後に`licenseMode`フィールドへ反映する。

### 6.4 UIへの含意

スクリーニング結果には「この値はESVD要約統計に基づく概算であり、ティアCとして扱われています」という表示を必須とする。

build-plan §5.2が「薄くしてよい項目」と明記している論点のため、実務上の標準値を採用する。

## 8. 決定事項 D-8:割引率の扱い(代替費用法・VFes)

### 8.1 代替費用法には割引現在価値化を含めない

**決定:** 代替費用法は「今この瞬間の代替調達コストはいくらか」という時間次元を持たない値(F-5c相当)として扱う。将来コストの割引現在価値化は含めない。

**理由:** IFVIのVFaccessが既に「将来の水アクセス費用(水ストレス悪化を見込み、2%・2080年まで割引)」という概念を独自方式でモデル化している。代替費用法にも同じ概念を別の割引率・別の方式で追加すると、「将来の水コスト」という同一概念が手法間で二重にモデル化され、M4の乖離分解の説明(「手法によって数えている範囲が違う」)がかえって曖昧になる。代替費用法は最もシンプルな現時点コストの基準値として位置づけ、将来コストの物語はIFVIのVFaccessに一元化する。

### 8.2 VFesは割引なし(時間次元を持たない値)として扱う

**確認結果(一次資料):** IFVI Water Consumption方法論のTransparency Report(Appendix H, Item 9「Accounting for future impacts」)は、割引について次のように述べる。

> "The value factor for financial costs to access future water captures future impacts through the year 2080. Future impacts are discounted using a 2% discount rate."

この記述は**VFaccessのみを指しており、VFesには一切言及がない。** 方法論文書のAppendix B(B19–B25、Altered Ecosystem Services)は、VFesを「2020年価格水準(2024年のデフレータで調整)のESVDバイオーム価値を2024年のAETデータで除したもの」と説明しており、将来年・投影期間・割引率への言及が一切ない。これは直後のセクション(B26–B33、Financial Costs to Access Future Water、2024→2080年の投影と2%割引を明示)と明確に対照的である。

**結論:** VFesは静的な現時点評価であり、`discountRateStatus: "no_time_dimension"`とする(VFnutrition・VFdiseaseと同じ扱い)。**これは「VFesは割引されない」という明示的な一文があるわけではなく、割引に関する記述が一切存在しないこと・VFaccessのセクションとの対比から導いた結論である。** この確度の性質(明示的確認ではなく不在の確認)を、`method-recalculability.md`に明記する。

**副次的な確認:** これによりIFVIの集計式`MAX(VFnutrition, VFdisease, VFes)`でMAXを取られる3つの値は、いずれも割引されない同一時間軸の値であることが確定した。時間軸の異なる値同士でMAXを取るという分析的な不整合の懸念は解消された。
